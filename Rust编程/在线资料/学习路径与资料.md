# 学习路径与资料

> [!summary] 一句话理解
> Rust 的学习曲线集中在**所有权与借用**这一段。过了这关，后面的异步、并发、生态都比较顺。
>
> 推荐的路径是：**官方书通读一遍 → Rustlings 练手 → 写一个真实小工具 → 再回头补异步与 unsafe**。不要一上来啃 Nomicon。

## 1. 分阶段学习路径

| 阶段 | 目标 | 主要材料 | 产出 |
|---|---|---|---|
| ① 语法与工具链 | 能读懂并写简单程序 | The Book 前半、[Rust by Example](https://doc.rust-lang.org/rust-by-example/) | 跑通 `cargo new/build/run/test` |
| ② 所有权与借用 | **过关的关键** | The Book 第 4、10、13 章 + [Rustlings](https://github.com/rust-lang/rustlings) | 能看懂借用检查器报错并自己修 |
| ③ 工程能力 | 能组织多模块项目 | Cargo Book、[[Rust编程/工程/Cargo 工作区与依赖管理]] | 用 clap + serde 写一个 CLI 工具 |
| ④ 并发与异步 | 能写并发程序 | Async Book、[[Rust编程/并发/async 与 Tokio 入门]] | 用 axum 写一个小 HTTP 服务 |
| ⑤ 深入 | 理解底层与边界 | Nomicon、Perf Book、unsafe 实践 | 能读标准库/知名 crate 源码 |

> [!tip] 最有效的两个动作
> 1. **Rustlings 必须做**：它把借用检查器的每种报错做成小练习，做完一遍比读三遍书管用
> 2. **尽早写一个真实工具**：把日常某个脚本用 Rust 重写一遍，你会自然遇到 `Result`、`clap`、`serde`、错误处理这些真实问题

## 2. 官方第一梯队（必读）

| 材料 | 说明 |
|---|---|
| [The Rust Programming Language](https://doc.rust-lang.org/book/)（[中文版](https://kaisery.github.io/trpl-zh-cn/)） | 官方教材，俗称 “The Book”。**第一本就读它** |
| [Rust by Example](https://doc.rust-lang.org/rust-by-example/) | 用可运行示例讲语法，适合当手册速查 |
| [Rustlings](https://github.com/rust-lang/rustlings) | 官方练习题集，专治借用检查器 |
| [std 标准库文档](https://doc.rust-lang.org/std/) | 最权威的 API 参考；注意看每个方法的**示例和 Panics 说明** |
| [The Cargo Book](https://doc.rust-lang.org/cargo/) | Cargo 的完整参考 |
| [The Rust Reference](https://doc.rust-lang.org/reference/) | 语义与语法规范，查“到底怎么定义的”时用 |
| [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/) | **写库的命名与设计规范**，做开源必读 |
| [Rust Playground](https://play.rust-lang.org/) | 在线编译，验证小片段最快 |

## 3. 进阶材料

| 材料 | 说明 |
|---|---|
| [The Rustonomicon](https://doc.rust-lang.org/nomicon/) | 死灵书，讲 unsafe、内存模型、`Pin`。**写到 unsafe 再看** |
| [Asynchronous Programming in Rust](https://rust-lang.github.io/async-book/) | 异步官方书，讲 `Future`、`Pin`、执行器原理 |
| [Too Many Linked Lists](https://rust-unofficial.github.io/too-many-lists/) | 用链表把所有权、`Rc`、`RefCell`、`unsafe` 串一遍，**极佳的进阶练手** |
| [Rust Design Patterns](https://rust-unofficial.github.io/patterns/) | 惯用法与反模式 |
| [Effective Rust](https://www.lurklurk.org/effective-rust/) | 类似 Effective C++ 的条目式建议 |
| [The Rust Performance Book](https://nnethercote.github.io/perf-book/) | 性能优化手册，作者是 rustc 性能团队成员 |
| [Comprehensive Rust](https://google.github.io/comprehensive-rust/) | Google 的四天培训教材，适合有经验的人快速过一遍 |
| [Rust Cookbook](https://rust-lang-nursery.github.io/rust-cookbook/) | 常见任务的配方集 |

> [!note] 阅读顺序的建议
> 很多人卡在 Nomicon 上，因为它是“编译器实现者视角”的文档。**先用标准库和生态把事做完**，等真的需要写 `unsafe` 或实现底层容器时再回头读，效果完全不同。

| [cargo-deny](https://github.com/EmbarkStudios/cargo-deny) | 许可证/安全/重复版本策略检查 | `cargo install cargo-deny` |

日常最小组合：

```bash
rustup component add rustfmt clippy rust-src
cargo install cargo-watch cargo-expand cargo-nextest
```

国内环境记得先配镜像源，见 [[Rust编程/工程/Cargo 工作区与依赖管理|Cargo 工作区与依赖管理]]。

## 7. 常见误区

> [!warning] 六个高频误区
> 1. **“先学 unsafe 再学安全 Rust”** —— 顺序反了。`unsafe` 是给已经理解所有权模型的人用的逃生舱，不是入门路径
> 2. **“借用检查器是障碍”** —— 它拦下的绝大多数是真实 bug（悬垂、数据竞争、迭代中修改）。遇到报错先想语义，不要立刻 `clone()`
> 3. **“`Rc<RefCell<T>>` 是通用解法”** —— 那是把编译期检查换成运行时检查，会 panic，也容易造成环引用泄漏。先用所有权和借用解决问题
> 4. **“async 一定比线程快”** —— async 的收益只在 IO 等待为主的场景成立；CPU 密集型用 `rayon` 或线程池
> 5. **“clone 一下就好了”** —— 编译能过，但可能把零拷贝设计变成大量分配。**先读一遍 `#[derive(Clone)]` 的字段到底有多大**
> 6. **“标准库什么都有”** —— 标准库刻意很小（无 HTTP、JSON、随机数、时间）。这是稳定性与维护成本的取舍，不是缺陷

## 9. 小结

> [!summary] 关键判断
> 1. **The Book + Rustlings** 是投入产出比最高的起点
> 2. 学习曲线的重心在**所有权与借用**，过了这关后面都顺
> 3. **尽早用 Rust 写一个真实工具**，比继续读书有效得多
> 4. `unsafe`、Nomicon、`Pin` 放到真正需要时再学
> 5. 追踪生态看 **This Week in Rust**，查 API 用 **docs.rs**，选库用 **lib.rs**
