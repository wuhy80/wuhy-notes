| In the last lesson we explored the structure of a neural network. Now, let's talk about how the network learns by seeing many labeled training data. ## 网络如何学习（How the Network Learns）

| 原文 | 译文 |
|---|---|
| What makes machine learning different from other computer science is that you don't explicitly write instructions for doing a particular task. In this case, you never actually write an algorithm for recognizing digits. Instead, you write an algorithm that can take in a bunch of example images of handwritten digits along with labels for what they are and adjust those 13,002 weights and biases of the network to make it perform better on those examples. | 机器学习与其他计算机科学的分野在于：你不用为某个特定任务显式地写出指令。就本例而言，你从不真正去写一个「识别数字」的算法；你写的是另一个算法——它接收一堆手写数字的示例图像和各自的标签，然后调整网络的那 13,002 个权重和偏置，让网络在这些样本上表现更好。 |
| The labeled images we feed in are collectively known as the "training data". | 我们喂进去的这些带标签图像，统称为「训练数据」（training data）。 |
| The network learns by looking at examples of correctly identified digits. | 网络靠看大量「已正确识别」的数字例子来学习。 |
| Hopefully, the layered structure will mean that what it learns generalizes to images beyond the training data. To test this, after training the network, we can show it more labeled data that it's never seen before and see how accurately it classifies them. | 但愿这种分层结构意味着：它学到的东西能泛化（generalize）到训练数据之外的图像。为了验证这一点，训练完网络后，我们可以给它看更多它从未见过的带标签数据，看它分类得有多准。 |
| We use some of the data for training the network and some other data it's never seen before for testing it after it's trained. | 我们用一部分数据训练网络，再用它从未见过的另一部分数据，在训练结束后做测试。 |
| This process requires a _lot_ of data. Fortunately, the good people behind the [MNIST database](http://yann.lecun.com/exdb/mnist/) have put together a collection of tens of thousands of handwritten digit images, each labeled with the number they are supposed to be, that we can use for free. | 这个过程需要_海量_数据。幸运的是，MNIST 数据库背后的好心人们已经整理了几万张手写数字图像，每张都标着它该是哪个数字，我们可以免费用。 |
| I should point out that although it can be provocative to describe a machine as "learning", once you see how it works, it feels a lot less like some crazy sci-fi premise and a lot more like a calculus exercise. It really just comes down to finding the minimum of a specific function. | 需要指出：把机器描述成在「学习」固然听着挺耸动，可一旦看清它的原理，它就远没那么像疯狂的科幻设定，反倒更像一道微积分练习题。说到底，它就是求某个特定函数的最小值。 |
| The process of learning is essentially just finding lower and lower points on a specific function. | 学习的过程，本质上就是在一个特定函数上不断寻找越来越低的点。 |

> - **generalize** /ˈdʒenrəlaɪz/ —— 泛化。机器学习核心术语：学到的东西能否推广到没见过的数据。
> - **classify** /ˈklæsɪfaɪ/ —— 分类。how accurately it classifies them 它分类得有多准。
> - **provocative** /prəˈvɒkətɪv/ —— 耸动的、容易引起争议的。it can be provocative to do sth 这么说难免有博眼球之嫌。
> - **premise** /ˈpremɪs/ —— 前提、设定。sci-fi premise 科幻设定。
> - *come down to ...* —— 归结为、说到底就是。It really just comes down to... 说穿了就是……。

## 代价函数（The Cost Function）

| 原文 | 译文 |
|---|---|
| Remember, our network's behavior is determined by all of its weights and biases. The weights represent the strength of connections between each neuron in one layer and each neuron in the next. And each bias is an indication of whether its neuron tends to be active or inactive. | 记住，网络的行为由它的全部权重和偏置决定。权重代表一层里每个神经元与下一层每个神经元之间连接的强度；而每个偏置则提示着它那个神经元倾向于激活还是沉默。 |
| The behavior of the network depends on its weights and biases. | 网络的行为取决于它的权重和偏置。 |
| To start things off, initialize all the weights and biases to be random numbers. This network will perform horribly on the given training example since it's just doing something random. | 万事开头：先把所有权重和偏置初始化成随机数。这个网络在给定训练样本上的表现会一塌糊涂，因为它就是在瞎来。 |
| For example, if you feed in this image of a 3, the output layer just looks like a mess: | 比如，喂进这张数字 3 的图像，输出层看上去就是一团乱麻： |
| Initialized with totally random weights and biases, the network is terrible at identifying digits. | 用完全随机的权重和偏置初始化之后，这个网络识别数字的水平惨不忍睹。 |
| So how do you programmatically identify that the computer is doing a lousy job and then help it improve? | 那么，怎么用程序判断出计算机干得有多烂，再帮它改进呢？ |
| What you do is define a cost function, which is a way of telling the computer, "No, bad computer, that output layer should have activations which are 0 for most neurons, but with a 1 for the third neuron. What you gave me is utter trash!" | 你要做的，是定义一个代价函数（cost function）——它相当于告诉计算机：「不对，坏计算机，输出层本该是大多数神经元激活值为 0、只有第三个神经元为 1。你交给我的这堆玩意儿是彻头彻尾的垃圾！」 |
| We measure how badly the network is doing by comparing its results to the correct answer. | 我们把网络的结果与正确答案相比较，来度量它做得有多糟。 |
| To say that a little more mathematically, add up the squares of the differences between each of these trash output activations and the values you want them to have. We'll call this the "cost" of a single training example. | 用更数学一点的话说：把这些垃圾输出激活值各自与你期望值之差的平方统统加起来。我们就把它叫作单个训练样本的「代价」（cost）。 |
| The cost is small when the network confidently classifies this image correctly but large when it doesn't know what it's doing. | 网络自信地把这张图分类正确时，代价就小；它不知所云时，代价就大。 |
| Suppose the network is shown an image of a 4. Rank the costs associated with each of the possible outputs shown above. | （译注：原文此处是一道互动测验，需到官网原页体验——上方的配图给出 A、B、C、D 四种可能的输出。）假设给网络看一张数字 4 的图像，请给上图中各种可能输出所对应的代价排个序。 |
| B has the lowest cost because it is the ideal output, and D has the highest cost because it is the worst possible output. | B 的代价最低，因为它是理想输出；D 的代价最高，因为它是最糟糕的输出。 |
| A has a relatively small cost because nine of the ten output values are perfect, and only the output neuron corresponding to the digit 4 is wrong. C has a much higher cost than A because _all_ of its output neurons are wrong, seemingly by quite a lot. | A 的代价相对较小，因为十个输出值里有九个完美无缺，只有对应数字 4 的那个输出神经元错了。C 的代价远高于 A，因为它的输出神经元_全_错了，而且错得似乎还挺离谱。 |

> [!note]- 词汇注释 · 代价函数
> - **initialize** /ɪˈnɪʃəlaɪz/ —— 初始化。initialize ... to be random numbers 初始化成随机数。
> - **horribly** /ˈhɒrəbli/ —— 糟糕透顶地。perform horribly 表现一塌糊涂。
> - **lousy** /ˈlaʊzi/ —— 糟糕的、蹩脚的。a lousy job 活儿干得很烂；注意与 jealousy 无关，来自 louse（虱子）。
> - **programmatically** /ˌprəʊɡrəˈmætɪkli/ —— 以编程方式、用程序自动地。
> - **utter** /ˈʌtə/ —— 彻底的、十足的（形容词）。utter trash 彻头彻尾的垃圾；utter 作动词则是「说出」。
> - **trash** /træʃ/ —— 垃圾（口语）。本节的喜剧关键词：trash output activations 垃圾输出激活值。

## 大批样本上的代价（The Cost Over Many Examples）

| 原文 | 译文 |
|---|---|
| But we aren't just interested in how the network performs on a _single_ image. To really measure its performance, we need to consider the **average** cost over all the tens of thousands of training examples. This average is our measure of how lousy the network is and how bad the computer should feel. | 但我们关心的不只是网络在_单个_图像上的表现。要真正衡量它的性能，得考虑全部几万个训练样本的**平均**代价。这个平均值，就是我们的标尺：量一量网络有多烂、计算机该有多内疚。 |
| This is, to put it lightly, a complicated function. Remember how the network itself is a function? It has 784 inputs (the pixel values), 10 outputs, and 13,002 parameters. | 说得委婉些，这是一个相当复杂的函数。还记得网络本身就是个函数吗？它有 784 个输入（像素值）、10 个输出，外加 13,002 个参数。 |
| The neural network is a function that takes in images and spits out digit predictions based on the weights and biases. | 神经网络是一个函数：输入图像，基于权重和偏置吐出数字预测。 |
| The cost function is a layer of complexity on top of that. The inputs of the cost function are those 13,002 weights and biases, and it spits out a single number describing how bad those weights and biases are. | 代价函数则在其上又叠了一层复杂度。它的输入就是那 13,002 个权重和偏置，输出是一个单独的数，描述这组权重和偏置有多糟糕。 |
| It's defined in terms of the network's behavior on all the tens of thousands of pieces of labeled training data. In other words, this training data is a massive set of parameters to the cost function. | 它的定义，依据的是网络对全部几万条带标签训练数据的行为。换句话说，这些训练数据本身就是代价函数的一大堆参数。 |
| The cost function takes in the weights and biases of a network and uses the training images to compute a "cost," measuring how bad the network is at classifying those training images. | 代价函数接收网络的权重和偏置，利用训练图像算出一个「代价」，衡量网络在分类这些训练图像这件事上有多糟糕。 |

> - *to put it lightly* —— 说得委婉些（常作反语：实际程度远超字面）。
> - **spit out** —— 吐出、输出（口语）。spits out a single number 吐出一个数。
> - **parameter** /pəˈræmɪtə/ —— 参数。13,002 parameters。
> - *a layer of complexity on top of ...* —— 在……之上再叠一层复杂度。layer 一语双关：既是网络的层，也是「一层」复杂度。
> - *in terms of ...* —— 依据、基于、就……而言。

## 最小化代价函数（Minimizing the Cost Function）

| 原文 | 译文 |
|---|---|
| Just telling the computer what a terrible job it's doing isn't very helpful. You want to tell it how it should change those 13,002 weights and biases so as to improve. | 光告诉计算机「你干得有多糟」没什么用。你得告诉它，该怎么改动那 13,002 个权重和偏置才能进步。 |
| We can do better! Growth mindset! | 我们可以做得更好！成长型思维！ |
| To make it easier, rather than struggling to imagine this cost function with 13,002 inputs, let's imagine a simple function with one number as an input, and one number as an output. | 为了容易起见，别费劲去想象这个有 13,002 个输入的代价函数了，我们先想象一个简单的函数：一个数作输入，一个数作输出。 |
| In this simple example, we'll imagine that the cost function takes just one input (although, in reality, ours takes 13,002 inputs). How do we find an input that minimizes the cost? | 在这个简单例子里，我们假设代价函数只取一个输入（尽管现实中我们的函数要吃 13,002 个输入）。怎么找到一个让代价最小的输入呢？ |
| How do you find an input that minimizes the value of this cost function? | 你要怎样找到一个输入，让这个代价函数的值最小？ |
| Calculus students will know you can sometimes figure out that minimum explicitly by solving for when the slope is zero. However, that's not always feasible for really complicated functions, and it certainly won't be for our 13,002-input function defined in terms of an ungodly number of parameters. | 学过微积分的人会知道：有时可以通过解出「斜率为零」的点，把那个最小值显式求出来。然而，对真正复杂的函数这并不总是可行；对我们这个由天文数字般多的参数定义、还带 13,002 个输入的函数，就更不用想了。 |
| For a complicated cost function, computing the exact minimum directly isn't going to work. | 对复杂的代价函数来说，直接算出精确最小值这条路是走不通的。 |
| A more flexible tactic is to start at a random input and figure out which direction to step to make the output lower. Specifically, find the slope of the function where you are. If the slope is negative, shift to the right. If the slope is positive, shift to the left. | 更灵活的策略是：从一个随机输入出发，弄清往哪个方向迈一步能让输出变低。具体来说，求出你所在位置的斜率：斜率为负就往右移，斜率为正就往左移。 |
| By following the slope (moving in the downhill direction), we approach a local minimum. | 顺着斜率走（朝下坡方向移动），我们便逼近一个局部最小值（local minimum）。 |
| Checking the new slope at each point and doing this repeatedly, you approach some local minimum of the function. | 每到一点就查看新的斜率，如此反复，你就能逼近函数的某个局部最小值。 |
| The image to have in mind is a ball rolling down a hill: | 你脑海里该有的画面，是一颗球滚下山坡： |
| Moving the input position according to the slope is a lot like a ball rolling down a hill. | 按斜率移动输入的位置，就很像一颗球滚下山坡。 |
| Notice, even for this simplified single-input cost function, there are many possible valleys you might land in. It depends on which random input you start at, and there's no guarantee that the local minimum you land in will be the smallest possible value for the cost function. | 注意，即便对这个简化过的单输入代价函数，你可能落进的山谷也有很多个。这取决于你从哪个随机输入出发，而且没法保证你落进的局部最小值，就是代价函数可能取到的最小值。 |
| Also, notice how if you make your step sizes proportional to the slope itself when the slope flattens out towards a minimum, your steps will get smaller and smaller, and that keeps you from overshooting. | 另外注意：如果你让步长与斜率本身成正比，那么当斜率在趋近最小值处变平时，你的步子会越迈越小，这就防止你冲过头（overshoot）。 |
| As the slope gets shallower, take smaller steps to avoid overshooting the minimum. | 斜率越平缓，步子就迈得越小，以免冲过最小值。 |
| Bumping up the complexity a bit, imagine a function with two inputs and one output. You might think of the input space as the xy-plane, with the cost function graphed as a surface above it. | 把复杂度调高一档：想象一个有两个输入、一个输出的函数。你可以把输入空间想成 xy 平面，代价函数则画成它上方的一个曲面。 |
| We can imagine minimizing a function that takes two inputs (which is still not 13,002 inputs, but it's one step closer). Starting with a random value, look for the downhill direction and repeatedly move that way. | 我们可以想象最小化一个有两个输入的函数（虽然还不是 13,002 个输入，但总算近了一步）。从一个随机值出发，寻找下坡方向，然后反复朝那个方向移动。 |
| Instead of asking about the slope of the function, you ask which direction you should step in this input space to decrease the output of the function most quickly. Again, think of a ball rolling down a hill. | 这时你问的不再是「函数的斜率是多少」，而是「在这个输入空间里，该往哪个方向迈步才能让函数输出下降得最快」。同样，想想那颗滚下山的球。 |

> [!note]- 词汇注释 · 最小化代价函数
> - **slope** /sləʊp/ —— 斜率。solving for when the slope is zero 解斜率为零的点。
> - **feasible** /ˈfiːzəbl/ —— 可行的。not always feasible 并不总是可行。
> - **tactic** /ˈtæktɪk/ —— 策略、招数。a more flexible tactic 更灵活的策略。
> - **ungodly** /ʌnˈɡɒdli/ —— 大得吓人的、离谱的（口语夸张）。an ungodly number of parameters。
> - **local minimum** —— 局部最小值。与之相对的是 global minimum 全局最小值。
> - **overshoot** /ˌəʊvəˈʃuːt/ —— 冲过头、越过目标。keeps you from overshooting 防止你冲过头。
> - *bump up ...* —— 把……调高一档、增加。bump up the complexity 提高复杂度。

## 超越斜率：用上梯度（Beyond Slope: Using The Gradient）

| 原文 | 译文 |
|---|---|
| In this higher-dimensional space, it doesn't really make sense to talk about the "slope" as a single number. Instead, we need to use a vector to represent the direction of steepest ascent. | 在这个更高维的空间里，再用一个单独的数去谈「斜率」就不太说得通了。我们需要用一个向量来表示最陡上升的方向。 |
| Those of you familiar with multivariable calculus will know that this vector is called the "gradient", and it tells you which direction you should step to _increase_ the function most quickly. | 熟悉多元微积分（multivariable calculus）的朋友会知道，这个向量叫「梯度」（gradient），它告诉你往哪个方向迈步能让函数_上升_得最快。 |
| Naturally enough, taking the negative of that vector gives you the direction to step which _decreases_ the function most quickly. What's more, the length of that gradient vector is an indication for just how steep that steepest slope is. | 顺理成章地，取这个向量的负向量，得到的就是让函数_下降_得最快的迈步方向。而且，这个梯度向量的长度还提示了：那条最陡的坡究竟有多陡。 |
| The gradient, $\nabla C$, gives the uphill direction, so the negative of the gradient, $-\nabla C$, gives the downhill direction. | 梯度 $\nabla C$ 给出上坡方向，因此梯度的负向量 $-\nabla C$ 给出下坡方向。 |
| To those of you unfamiliar with multivariable calculus, check out some of [the work I did for Khan Academy on the topic](https://www.khanacademy.org/math/multivariable-calculus). | 对不熟悉多元微积分的朋友，可以看看我为可汗学院（Khan Academy）做的[这方面的内容](https://www.khanacademy.org/math/multivariable-calculus)。 |
| Honestly though? All that matters for you and me right now is that in principle, there exists a way to compute this vector, which tells you both what the "downhill" direction is, and how steep it is. | 不过说实在的？眼下对你我来说，要紧的只有一件事：原则上，确实存在一种计算这个向量的办法，它既能告诉你「下坡」方向是哪边，也能告诉你这个坡有多陡。 |
| You'll be okay even if you're not rock solid on the details. | 就算细节上你没十拿九稳，也照样没问题。 |
| So the algorithm for minimizing this function is to compute this gradient direction, take a step downhill, and repeat that over and over. This process is called "gradient descent." | 于是，最小化这个函数的算法就是：算出梯度方向，朝下坡迈一步，然后不断重复。这个过程就叫「梯度下降」（gradient descent）。 |
| Gradient descent just means walking in the downhill direction to minimize the cost function. | 梯度下降的意思说白了，就是沿着下坡方向走，把代价函数最小化。 |
| And remember, our cost function is specially designed to measure how bad the network is at classifying the training examples. So changing the weights and biases to decrease the cost will make the network's performance better! | 而且别忘了，我们的代价函数本来就是专门用来度量「网络分类训练样本有多糟」的。所以，通过改动权重和偏置让代价下降，网络的表现就会变好！ |
| In practice, each step will look like $-\eta \nabla C$ where the constant $\eta$ is known as the learning rate. The larger it is, the bigger your steps, which means you might approach the minimum faster, but there's a risk of overshooting and oscillating a lot around that minimum. | 实践中，每一步形如 $-\eta \nabla C$，其中常数 $\eta$ 就是所谓的「学习率」（learning rate）。它越大，你的步子就越大——你可能更快逼近最小值，但也有风险冲过头，在最小值附近来回震荡。 |
| It's the same basic idea for a function with 13,002 inputs instead of two inputs. I'm still showing the picture of a function with two inputs because nudges to a 13,002-dimensional input are a little hard to wrap your mind around. But let me give you a non-spatial way to think about it. | 换成有 13,002 个输入（而不是两个输入）的函数，基本思路一模一样。我仍然展示两输入函数的图像，是因为对一个 13,002 维的输入做「微调」，实在有点难以想象。不过，让我给你一个不靠空间想象的思路。 |

> [!note]- 词汇注释 · 超越斜率：用上梯度
> - **gradient** /ˈɡreɪdiənt/ —— 梯度。多元微积分的核心概念，本篇主角。
> - **multivariable** /ˌmʌltiˈveəriəbl/ —— 多变量的。multivariable calculus 多元微积分。
> - **steepest ascent** —— 最陡上升。ascent /əˈsent/ 上升；反义 descent /dɪˈsent/ 下降。
> - **in principle** —— 原则上、理论上。
> - *rock solid* —— 十拿九稳、非常扎实。not rock solid on the details 细节上不牢靠。
> - **learning rate** —— 学习率。符号 $\eta$（eta），控制每步走多远的比例系数。
> - **oscillate** /ˈɒsɪleɪt/ —— 震荡、来回摆动。oscillating around that minimum。
> - *wrap your mind around ...* —— 把脑子绕明白、想象明白。难懂的东西 hard to wrap your mind around。

## 理解梯度的另一种方式（Another Way to Think About The Gradient）

| 原文 | 译文 |
|---|---|
| Imagine organizing all the weights and biases for the entire network into one big column vector with 13,002 entries. Then the negative gradient of the cost function will also be a vector with 13,002 entries. | 想象把整个网络的所有权重和偏置，整理成一个有 13,002 项的大列向量。那么，代价函数的负梯度也会是一个有 13,002 项的向量。 |
| The vector on the left is a list of all the weights and biases for the entire network. | 左边的向量，是整个网络全部权重和偏置的一份清单。 |
| The vector on the right is the negative gradient, which is just a list of all the little nudges you should make to the weights and biases (on the left) in order to move downhill. | 右边的向量是负梯度——它其实就是一份清单，列出了为了让网络走下坡，你该对（左边那些）权重和偏置做的每一次小小调整。 |
| The negative gradient is a vector direction in this insanely huge input space that tells you what nudges to those 13,002 numbers would cause the most rapid decrease to the cost function. | 负梯度就是在这个大得疯狂的输入空间里的一个向量方向，它告诉你：对那 13,002 个数做怎样的微调，能让代价函数下降得最快。 |
| Each component of the negative gradient vector tells us two things. The sign, of course, tells us whether the corresponding component of the input vector should be nudged up or down. | 负梯度向量的每个分量都告诉我们两件事。符号当然告诉我们：输入向量中对应的分量该往上推还是往下压。 |
| But importantly, the relative magnitudes of the components in this gradient tells us which of those changes matters more. | 更重要的是，梯度中各分量的相对大小，告诉我们哪些改动更要紧。 |
| You see, in our network, an adjustment to one weight might have a greater impact on the cost function than an adjustment to some other weight. Consider the image below, and suppose that the network is supposed to be classifying its input as a "3". | 要知道，在我们的网络里，改动某个权重对代价函数的影响，可能比改动另一个权重大得多。看看下图，并假设网络本该把它的输入分类为「3」。 |
| Some weights have a larger impact on the cost than others. | 有些权重对代价的影响比别的更大。 |
| Some of these connections just matter more for our training data than others, and a way you can think about the gradient of our massive cost function is that it encodes the relative importance of each weight and bias. That is, which changes will carry the most bang for your buck. | 这些连接里，有些对我们的训练数据就是比别的更要紧。对这个庞大代价函数的梯度，你可以这样理解：它把每个权重和偏置的相对重要性编码了进去——也就是说，它标出哪些改动最划算。 |
| So if the cost function is a layer of complexity on top of the original neural network function, its gradient is one more layer of complexity still, telling us what nudge to all these weights and biases causes the fastest change to the value of the cost function. | 所以，如果说代价函数是在原神经网络函数之上叠的一层复杂度，那么它的梯度就是再往上叠的一层：它告诉我们，对所有这些权重和偏置做怎样的微调，能让代价函数的值变化得最快。 |
| The negative gradient tells us how to change the weights and biases to decrease the cost most effectively. | 负梯度告诉我们：怎样改动权重和偏置，才能最有效地降低代价。 |
| The algorithm for computing the value of this gradient vector efficiently is called backpropagation, which we'll dig into in the next lesson. There, I want to take the time to really walk through what happens to each weight and bias for a given piece of training data, trying to give an intuitive feel for what's happening beyond the pile of relevant formulas. | 高效计算这个梯度向量取值的算法，叫作反向传播（backpropagation），下一课我们会深挖它。到那时，我会花时间认真过一遍：对一条给定的训练数据，每个权重和偏置身上究竟发生了什么，力求在一堆相关公式之外，给你一种直观的感受。 |
| The main thing I want you to understand here, independent of implementation details, is that when we refer to a network "learning", we mean changing the weights and biases to minimize a cost function, which improves the network's performance on the training data. | 撇开实现细节不谈，我希望你在这一课抓住的主旨是：当我们说网络在「学习」时，指的是改动权重和偏置去最小化一个代价函数，从而提升网络在训练数据上的表现。 |
| But before we continue on to learn the details of computing this gradient, let's take a brief sidestep to dig into what this network looks like after it's trained. | 但在继续学习计算这个梯度的细节之前，我们先短暂岔开一步，看看这个网络训练完之后长什么样。 |

> [!note]- 词汇注释 · 理解梯度的另一种方式
> - **nudge** /nʌdʒ/ —— 轻推、微调。本课高频词：little nudges to the weights 对权重的轻轻推动。
> - **component** /kəmˈpəʊnənt/ —— 分量、组成部分。each component of the gradient vector。
> - **magnitude** /ˈmæɡnɪtjuːd/ —— 大小、量级。relative magnitudes 相对大小。
> - **encode** /ɪnˈkəʊd/ —— 编码。it encodes the relative importance 把相对重要性编码进去。
> - *bang for your buck* —— 划算、花小钱办大事。carry the most bang for your buck 最划算的改动。
> - **insanely** /ɪnˈseɪnli/ —— 疯狂地（口语夸张）。insanely huge input space。
> - **sidestep** /ˈsaɪdstep/ —— 岔开一步、支线话题。take a brief sidestep 短暂岔开一步。
> - **implementation** /ˌɪmplɪmenˈteɪʃn/ —— 实现。implementation details 实现细节。
