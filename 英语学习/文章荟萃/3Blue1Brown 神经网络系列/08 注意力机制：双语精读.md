## 开篇与回顾（Introduction & Recap）

| 原文 | 译文 |
|---|---|
| In the last chapter, you and I started to step through the internal workings of a _transformer_, the key piece of technology inside large language models. Transformers first hit the scene in a (now-famous) paper called _**Attention** is All You Need_, and in this chapter you and I will dig into what this attention mechanism is, by visualizing how it processes data. | 上一章里，你我已经开始逐步拆解 transformer（变换器）的内部工作原理——它是大语言模型（large language model）里的关键技术。Transformer 最初亮相于一篇（如今已大名鼎鼎的）论文《_**Attention** is All You Need_》（注意力就是你所需要的一切）；在这一章，你我将通过可视化它处理数据的方式，深挖这个注意力机制（attention mechanism）到底是什么。 |
| As a quick recap, here is some context to have in mind. | 先快速回顾一下，下面这些背景知识要记在心里。 |
| The goal of the model that we began studying in the last chapter is to take in a piece of text and predict what will come next. | 我们上一章开始研究的那个模型，目标是读入一段文本，然后预测接下来会出现什么。 |
| The input text that is taken in is first broken up into little pieces that we call tokens, which are often words or pieces of words. This process, known as tokenization, is a preprocessing step that is done before any of the input actually enters the transformer. | 输入的文本会先被切成小块，我们把这些小块叫做 token（词元），它们通常是一个个单词，或者单词的碎片。这个过程称为分词（tokenization），是一个预处理步骤，发生在任何输入真正进入 transformer 之前。 |
| To make the examples in this lesson simpler for us to conceptualize, let's pretend that these _tokens_ are always just words. | 为了让本课的例子更容易想象，我们就假装这些 _token_ 全都是一个个完整的单词好了。 |
| The tokens then enter the transformer, where the first step is to associate each token with a high-dimensional vector, which we call its embedding. | 随后这些 token 进入 transformer，而第一步就是把每个 token 关联到一个高维向量上，这个向量我们称之为嵌入（embedding）。 |
| The important idea that we should have in mind as we continue into the attention mechanism is that directions in this high-dimensional space of all possible embeddings can correspond with meaning. | 在继续深入注意力机制之前，应当记住一个重要观念：在所有可能嵌入构成的这个高维空间里，不同的方向可以对应不同的含义。 |
| For example, in the last chapter we saw how direction can correspond to gender, in the sense that adding a certain step in this space can take you from the embedding of a masculine noun to the embedding of the corresponding feminine noun. | 比如上一章我们见过，方向可以对应性别——在这个空间里加上某一步位移，就能把一个阳性名词的嵌入，带到与之对应的阴性名词的嵌入上去。 |
| This is just one of the many examples of how directions in this high-dimensional space could correspond to aspects of a word's meaning. | 在这个高维空间里，方向对应词义某个侧面的例子还有很多，这只是其中之一。 |
| The aim of a transformer is to progressively adjust these embeddings so that they don't merely encode data of an individual word, but rather a much richer contextual meaning. | transformer 的目标，就是逐步调整这些嵌入，让它们不再只编码单个词自身的信息，而是承载丰富得多的上下文含义。 |
| The first step in a transformer is to associate each token with a high-dimensional vector, which we call its embedding. | transformer 的第一步，是把每个 token 关联到一个高维向量上，我们把这个向量称为它的嵌入。 |

## 动机示例（Motivating Examples）

| 原文 | 译文 |
|---|---|
| Consider these three phrases: | 来看这三个短语： |
| - American shrew **mole**. | - American shrew **mole**（美洲鼩鼹，一种小兽）。 |
| - One **mole** of carbon dioxide. | - 一**摩尔**的二氧化碳（化学计量单位）。 |
| - Take a biopsy of the **mole**. | - 给这颗**痣**做一次活检。 |
| You and I both know that the word **mole** in each of these sentences has a different meaning that's based on the context. | 你我心里都清楚：**mole** 这个词在这三句话里含义各不相同，全凭上下文决定。 |
| However, after the first step of a transformer - the embedding step that associates each token with a vector - the vector that's associated with the word **mole** would be the same in all of these cases, as this initial token embedding is effectively a lookup table with no reference to the context. | 然而，经过 transformer 的第一步——把每个 token 关联到一个向量的嵌入步骤——之后，这几种情形下与 **mole** 关联的向量都是同一个，因为这个初始 token 嵌入实质上就是一张查询表（lookup table），完全不参考上下文。 |
| It's only in the next step of the transformer, the attention block, when the surrounding embeddings have the chance to pass information into the mole embedding and update its values. | 只有到 transformer 的下一步——注意力块（attention block）——周围的嵌入才有机会把信息传进 mole 的嵌入里，更新它的取值。 |
| You might imagine that a well-trained model could associate multiple distinct directions in this embedding space with the multiple distinct meanings of the word mole. | 你可以设想：一个训练有素的模型，会在这个嵌入空间里把多个不同的方向，分别对应到 mole 一词的多个不同含义上。 |
| It is the job of an attention block to calculate what it needs to add to the generic embedding, as a function of its context, to move it to one of those specific directions. | 注意力块的任务，就是算出「该往这个通用嵌入上加什么」——这笔加项以上下文为函数——好把它挪到那些特定方向之一上。 |
| To take another example, consider the embedding of the word **tower**. | 再举一个例子：看看 **tower**（塔）这个词的嵌入。 |
| This is presumably some very generic, non-specific direction in the space, associated with lots of other large, tall nouns. | 它多半对应空间里一个非常泛化、不特指的方向，和许多其他「高大」系名词牵连在一起。 |
| If this word was immediately preceded by **Eiffel**, you could imagine wanting the mechanism to update this vector so that it points in a direction that more specifically encodes the Eiffel Tower, maybe correlated with vectors associated with Paris and France and things made of iron. | 如果这个词前面紧跟着 **Eiffel**（埃菲尔），你可以想象，我们会希望这个机制把这个向量更新成指向一个更明确编码「埃菲尔铁塔」的方向，说不定还和 Paris（巴黎）、France（法国）以及「铁制品」相关的向量扯上关系。 |
| If it was also preceded by the word **miniature**, then the vector should be updated even further so that it no longer correlates with large, tall things. | 如果前面还多了一个 **miniature**（微缩的），那这个向量就该再更新一步，让它不再与「高大事物」相关。 |
| This transfer of information from the embedding of one token to that of another can occur over potentially large distances and can involve information that's much richer than just a single word. | 这种从一个 token 的嵌入传往另一个 token 嵌入的信息传递，可能跨越相当远的距离，携带的信息也远比单个词丰富。 |
| To appreciate this point, consider how in the final step of the transformer that we saw last chapter, only the _last_ vector in the sequence is used to make the final prediction for what comes next. | 要体会这一点，回想一下上一章讲过的 transformer 最后一步：序列里只有_最后一个_向量，会被拿来对「接下来是什么」做最终预测。 |
| For example, imagine that the text we input was most of an entire mystery novel, all the way up to a point near the end, which reads: | 比如，设想我们输入的文本是一整本悬疑小说的大部分内容，一直读到临近结尾处，那里写道： |
| _Therefore the murderer was..._ | 因此，凶手就是…… |
| If the model is going to accurately predict the next word, that final vector in the sequence which began its life simply embedding the word _was_ will have to have been updated by all of the attention blocks to represent much more than the individual word. | 模型要想准确预测下一个词，序列末尾那个起初只是嵌入 _was_ 一词的最终向量，就必须已经被所有注意力块更新过，承载的内容远超这一个词本身。 |
| It will have to have somehow encoded _all of the information_ from the full context window that's relevant to predicting the next word. | 它必须以某种方式，把完整上下文窗口（context window）中与预测下一个词相关的_全部信息_都编码进去。 |

> [!note]- 词汇注释 · 动机示例
> - **mole** /məʊl/ —— 一词三义：鼹鼠（兽）／摩尔（化学单位）／痣（皮肤）。本文借它讲「同词异义，靠上下文区分」。
> - **biopsy** /ˈbaɪɒpsi/ —— 活检（活体组织检查）。take a biopsy of ... 对……做活检。
> - **lookup table** —— 查找表。查表即得、与上下文无关的映射。
> - **presumably** /prɪˈzjuːməbli/ —— 大概、据推测。比 probably 更书面。
> - **precede** /prɪˈsiːd/ —— 出现在……之前。be immediately preceded by＝紧挨着出现在前面。
> - **correlate with ...** —— 与……相关联。
> - *as a function of ...* —— 作为……的函数；随……而变。写作中表依赖关系的高频说法。
> - *to appreciate this point* —— 要体会这一点。appreciate 在此＝充分理解、领会。

## 注意力模式（The Attention Pattern）

| 原文 | 译文 |
|---|---|
| We'll begin by describing a **single head of attention**, and later we will see how the attention block consists of many different heads running in parallel. | 我们先从描述**单个注意力头（single head of attention）**开始，之后会看到，一个注意力块其实由许多并行运转、彼此不同的头组成。 |
| It helps to have a simple example to reference as we do this. Imagine that our input includes the phrase: | 这一路讲下来，手边有个简单例子可供对照会很有帮助。设想我们的输入里有这么一句话： |
| _A fluffy blue creature roamed the verdant forest._ | 一只毛茸茸的蓝色生物，漫步在青翠的森林里。 |
| Suppose that the only type of update that we care about, for now, is having the adjectives in the phrase adjust the initial embeddings of their corresponding nouns. | 假设眼下我们唯一在意的更新类型，是让句中的形容词去调整其对应名词的初始嵌入。 |
| Again, the initial embedding for each word is some high-dimensional vector that contains no reference to the context. | 再强调一次：每个词的初始嵌入是某个高维向量，其中不含任何对上下文的指涉。 |
| Actually, that's only partly true, as these embeddings also encode the position of the word. | 严格说，这话只对了一半，因为这些嵌入同时也编码了词的位置。 |
| There's a lot more for us to say about the specific way that the positions are encoded, but for now, all we need to know is that the entries of this vector are enough to tell you both what the word is as well as where it exists in the context. Let's go ahead and denote these embeddings with the letter $\vec{E}$. | 位置具体是怎么编码的，后面还有很多可讲；但眼下你只需知道：这个向量的各个分量，足以同时告诉你这个词「是什么」，以及它「在上下文的哪里」。我们就用字母 $\vec{E}$ 来记这些嵌入。 |
| Our goal is to have a series of computations produce a new refined set of embeddings $\vec{E}'$, where, in our case, those corresponding to the nouns have ingested the meaning from their corresponding adjectives. | 我们的目标，是让一系列计算产出一组新的、精炼过的嵌入 $\vec{E}'$——在我们的例子里，对应名词的那些嵌入已经把对应形容词的含义「吃」了进去。 |
| To be clear, this example of adjectives updating nouns is just to illustrate the _type of behavior_ that an attention head could be doing. The true behavior of an attention head is much harder to parse-as is with much of deep learning-as it's based on the tweaking and tuning of a huge number of parameters to minimize _some cost function_. | 说清楚一点：形容词更新名词这个例子，只是为了说明注意力头_可能在做_的_那一类行为_。注意力头真实的行为要难解读得多——深度学习的很多东西都是如此——因为它源于对海量参数的反复调整与微调，目标是让_某个代价函数_（cost function）最小化。 |
| As we explore all of the different matrices filled with parameters involved in this process, having a visual example of what the attention mechanism _might be doing_ will help us keep the concepts much more concrete. | 在我们探索这一过程里各种装满参数的矩阵时，有一个「注意力机制_可能在做什么_」的可视化例子垫底，会让这些概念具体得多。 |

> [!note]- 词汇注释 · 注意力模式
> - **head** /hed/ —— （注意力）头。single head 单头，multi-head 多头，注意不是「脑袋」。
> - **in parallel** —— 并行地、同时进行。
> - **fluffy** /ˈflʌfi/ —— 毛茸茸的、蓬松的。
> - **verdant** /ˈvɜːdnt/ —— 青翠的、苍翠的。roam the verdant forest，书面色彩很浓。
> - **roam** /rəʊm/ —— 漫游、闲逛。
> - **refined** /rɪˈfaɪnd/ —— 精炼的、精细化的。a refined set of embeddings 一组精炼过的嵌入。
> - **ingest** /ɪnˈdʒest/ —— 摄入、吞入。文中喻「把含义吸收进嵌入」。
> - **parse** /pɑːs/ —— 解析、解读。hard to parse＝难以解读。

## 查询（Queries）

| 原文 | 译文 |
|---|---|
| For the first step in this attention block, we can imagine each noun in the sentence asking the question: | 注意力块的第一步，我们可以想象句中的每个名词都在发问： |
| **"Hey, are there any adjectives sitting in front of me?"** | **「嘿，我前面是不是坐着几个形容词呀？」** |
| These questions, like the one asked by the noun _creature_, are somehow encoded as yet another vector that we call the **query**. | 这些问题——比如名词 _creature_ 问出的那个——会以某种方式被编码成又一个向量，我们称之为**查询（query）**。 |
| This query vector has a much smaller dimension than the embedding vector. | 这个查询向量的维度，比嵌入向量小得多。 |
| Computing this query looks like taking a certain matrix, which we'll label as $W_Q$, and multiplying it by the embedding of the word. Let's write the query vector as $\vec{Q}$. | 计算这个查询，看起来是这么回事：取某个矩阵——我们记作 $W_Q$——乘以这个词的嵌入。查询向量就写作 $\vec{Q}$。 |
| When we place a matrix next to an arrow, like $W_Q$ in the image, it's meant to represent that multiplying the matrix by the vector at the arrow's start returns the vector at the arrow's end. | 当我们把一个矩阵画在箭头旁边——比如图中的 $W_Q$——它的含义是：用这个矩阵去乘箭头起点处的向量，得到的就是箭头终点处的向量。 |
| In our case, we'll multiply this matrix $W_Q$ by all of the embeddings in the context and produce one query vector for each token. | 在我们的场景里，我们会用矩阵 $W_Q$ 乘以上下文中的全部嵌入，为每个 token 产出一个查询向量。 |
| The entries of the matrix $W_Q$ are the parameters of the model, meaning that their true behavior is learned from data. | 矩阵 $W_Q$ 的各个元素就是模型的参数（parameter）——也就是说，它们真实的行为是从数据里学出来的。 |
| In practice, what this query matrix does in a particular attention head is challenging to parse. | 实际上，这个查询矩阵在某个具体的注意力头里究竟在做什么，是很不容易解读的。 |
| Keep in mind, our nouns-and-adjectives example is made up. | 记住，我们这个「名词与形容词」的例子是编出来的。 |
| We're showing one behavior that the relevant matrix operations could plausibly implement. | 我们展示的，只是相关矩阵运算_有可能_实现的一种行为。 |
| Specifically, we're imagining that this $W_Q$ matrix maps the embeddings of nouns to a certain direction in this smaller query space that (somehow) encodes the notion of looking for adjectives in preceding positions. | 具体来说，我们是在设想：这个 $W_Q$ 矩阵把名词的嵌入，映射到这个更小的查询空间里的某个方向上，而那个方向（以某种方式）编码了「在前面的位置找形容词」这个概念。 |
| With this as our motivating example, you may very well ask: What does this matrix $W_Q$ do to non-noun embeddings? | 拿它当引子，你很自然会问：这个 $W_Q$ 矩阵对非名词的嵌入做了什么？ |
| Who knows. Maybe it's simultaneously trying to accomplish some other goal with them. | 天知道。也许它同时在拿它们实现什么别的目标。 |
| What we're focused on right now is what is happening with the nouns. | 我们此刻关注的，只是名词身上发生的事。 |

> [!note]- 词汇注释 · 查询
> - **query** /ˈkwɪəri/ —— 查询。数据库与检索语境的核心词，本文指注意力头里「发问」的向量。
> - **entry** /ˈentri/ —— （矩阵／向量的）元素、分量。
> - **parameter** /pəˈræmɪtə/ —— 参数。模型里从数据中学出来的可调量。
> - **be made up** —— 编造的、虚构的。make up a story＝编故事。
> - **plausibly** /ˈplɔːzəbli/ —— 说得通地、貌似合理地。
> - **map ... to ...** —— 把……映射到……。线性代数高频动词。
> - **simultaneously** /ˌsɪmlˈteɪniəsli/ —— 同时地。
> - *Who knows.* —— 天知道。口语里表示「没人说得清」。

## 键（Keys）

| 原文 | 译文 |
|---|---|
| At the same time, a second matrix - the **key matrix** - is also multiplied by each of the embeddings. This key matrix is full of tunable parameters, just like the query matrix. | 与此同时，第二个矩阵——**键矩阵（key matrix）**——也会乘到每一个嵌入上。这个键矩阵同样装满可调参数，跟查询矩阵一个样。 |
| The product is a second sequence of vectors that we call the **keys**. Conceptually, we want to think of these keys as potential answers to the queries. We'll label the key matrix as $W_k$ and the keys as $\vec{K}$. | 乘出来的结果，是第二组向量序列，我们称之为**键（key）**。概念上，不妨把这些键当作查询的潜在答案来想。键矩阵记作 $W_k$，键记作 $\vec{K}$。 |
| This key matrix, just like the query matrix, maps the embedding vectors to that same smaller dimensional space. | 这个键矩阵跟查询矩阵一样，把嵌入向量映射到同一个维度较小的空间。 |
| Conceptually, we want to think of the keys as matching the queries whenever they closely align with each other. In our made up example, we might imagine that the key matrix maps the adjectives like _fluffy_ and _blue_ to vectors that are closely aligned with the query produced by the word _creature_. | 概念上，我们希望这样想：只要键和查询彼此高度对齐，就算配对成功。在我们这个虚构的例子里，可以设想键矩阵把 _fluffy_、_blue_ 这类形容词，映射成与 _creature_ 产出的查询高度对齐的向量。 |
| The key produced by the word fluffy is closely aligned to the query produced by the word creature. | fluffy 一词产出的键，与 creature 一词产出的查询高度对齐。 |
| The way we measure how closely a given pair of key and query vectors align is to take their dot product. A larger dot product corresponds to stronger alignment. | 衡量一对键向量和查询向量对齐到什么程度，办法是取它们的点积（dot product）。点积越大，对齐越强。 |
| One way we could visualize this is as a grid of dots, where bigger dots correspond to larger dot products. | 一种可视化办法，是把它画成一张点阵图：点越大，代表点积越大。 |
| Larger dot products indicate higher alignment between the key and the query, while smaller dot products indicate weaker alignment. | 点积大，说明键与查询对齐程度高；点积小，则说明对齐程度弱。 |
| In our adjective-noun example, the grid would look like the one above. The keys produced by _fluffy_ and _blue_ align closely with the query produced by _creature_, resulting in the dot products in these two spots being large, positive numbers. | 在我们的形容词-名词例子里，网格就长成上图那样。_fluffy_ 和 _blue_ 产出的键与 _creature_ 产出的查询对得很齐，于是这两个位置上的点积是很大的正数。 |
| In machine learning terms, this indicates that the embeddings of _fluffy_ **attend to** the embeddings of _creature_. | Conceptually, we want to think of these keys as potential answers to the queries. | 概念上，我们把这些键当作查询的潜在答案来想。 |
| After computing all the dot products of the key-query pairs, we're left with this grid, containing values ranging from $-\infty$ to $\infty$, that displays a score of how relevant each word is to updating the meaning of every other word. | 把所有键-查询对的点积算完，我们手上就剩这张网格：取值从 $-\infty$ 到 $\infty$，给每个词打出了「对更新其他每个词的含义有多相关」的分数。 |
| The way we're about to use these scores is by taking a certain weighted sum along each column, weighted by the relevance. | 我们打算这样用这些分数：沿每一列做某种加权和，权重就取这个相关度。 |
| But first, instead of having values range from $-\infty$ to $\infty$, what we want is for the numbers in these columns to be between 0 and 1 and for each column to add up to 1, as if they were a probability distribution. | 但首先，与其让取值在 $-\infty$ 到 $\infty$ 之间撒开，我们想要的是：每列的数字都落在 0 和 1 之间，而且每列加起来恰好等于 1，就像一个概率分布。 |
| If you're coming from the last chapter, you're already familiar with what we need to do: compute a **softmax** along each one of these columns to normalize its values. | 如果你是从上一章一路看过来的，就已经知道接下来该怎么做了：对每一列计算一次 **softmax**，把数值归一化。 |
| After we apply softmax to all of the columns, we'll fill in the grid with these normalized values. We call this grid the **attention pattern**. | 对所有列都做过 softmax 之后，我们用这些归一化的值填满网格。这张网格，就叫做**注意力模式（attention pattern）**。 |
| At this point, we're safe to think about each column as giving weights according to how relevant the word on the left is to the corresponding value at the top. | 到这一步，你就可以放心地把每一列理解为：按左侧的词与顶部对应词的相关程度，给出权重。 |
| In the image, the word on the left, blue, holds a weight of 0.58 of relevance to the word on the top, creature. | 图里左侧的 blue 一词，对顶部的 creature 一词持有 0.58 的相关权重。 |
| The original transformer paper presents us with a really compact way to write this all down: | 最早的 transformer 论文给了我们一种极其紧凑的写法，能把这一切一笔写尽： |
| Here, the variables $Q$ and $K$ represent the full arrays of query and key vectors, respectively—those smaller vectors obtained by multiplying the embeddings by the query and key matrices. | 这里的变量 $Q$ 和 $K$，分别代表查询向量和键向量的完整阵列——也就是把嵌入乘以查询矩阵、键矩阵之后得到的那些较小的向量。 |
| And on the right side of the equation, the numerator in the softmax function, $K^TQ$, is a really compact way to represent the grid of all possible dot products between key-query pairs. | 再看等式右边：softmax 函数的分子 $K^TQ$，是「所有键-查询对之间全部可能点积」那张网格的极简写法。 |
| The conventions used by the Attention is All You Need paper differ from the one we use here. In their framing, the key and query vectors exist in the rows of the matrices K and Q respectively, whereas we framed it as columns. | 《Attention is All You Need》论文用的约定和我们这里不同。在他们的框架里，键向量和查询向量分别排在矩阵 K 和 Q 的行里；而我们把它们排成了列。 |
| Also, for the attention pattern, they show the expression $QK^T$. This means where we have keys on the left, and queries on the top, they would have queries on the left, and keys on the top, so the whole diagram is flipped diagonally. | 另外，注意力模式他们写成 $QK^T$。这意味着：我们这边键在左、查询在顶，他们那边则是查询在左、键在顶，整张图表沿对角线翻了个面。 |
| A small technical detail that we didn't mention is that for numerical stability, it's helpful to divide all of these values by the square root of the dimension of that key-query space, hence the denominator $\sqrt{d_k}$. | 还有个之前没提的小技术细节：出于数值稳定性的考虑，最好把所有这些值都除以键-查询空间维度的平方根，于是就有了分母 $\sqrt{d_k}$。 |
| And that softmax function that's wrapped around the full expression is meant to be understood as applying **softmax** column by column. | 而包住整个表达式的那个 softmax 函数，应当理解为逐列施加 **softmax**。 |

| 原文 | 译文 |
|---|---|
| We've said earlier that, during the training process, the model is run on a given text example. Then the model's weights are adjusted to either reward or punish it based on the probability it assigns to the _true next word_. | 前面说过，在训练过程中，模型会在给定的文本样例上跑一遍。随后，根据模型赋予_真实的下一个词_的概率高低，对它进行奖励或惩罚，调整模型的权重。 |
| There's actually more to it. It turns out that, to make the process more efficient, the model also simultaneously predicts every possible next token following each subsequence of tokens in the passage. | 其实事情还不止如此。为了提高效率，模型还会同时预测：文中每个 token 子序列（subsequence）后面，下一个可能的 token 是什么。 |
| A model being trained on the phrase: **_A fluffy blue creature roamed the verdant forest._** might also be predicting what words follow _creature_ and what words follow _the_, and everything else along the way. | 用 **_A fluffy blue creature roamed the verdant forest._** 这句话训练的模型，可能同时也在预测 _creature_ 后面接什么词、_the_ 后面接什么词——一路上的每个位置都不放过。 |
| This makes the training process much more efficient, as what would otherwise be a single training example effectively acts as many. | 这让训练过程高效得多：原本只能算一个训练样例的句子，实际上顶得上许多个。 |
| For the purposes of our attention pattern, this also means that we would never want words that appear _later_ in the input to influence words that appear _earlier_, since otherwise they could kind of give away the answer for what comes next. | 就我们的注意力模式而言，这也意味着：我们绝不希望输入里_靠后_的词去影响_靠前_的词，否则它们多多少少会把「接下来是什么」的答案提前泄露出去。 |

That way, after applying softmax, all of those spots get turned into zero, but the columns stay normalized. | 在应用 softmax 之前把它们强制置零的常见做法，是把这些位置的元素统统设成负无穷。这样一来，softmax 一过，那些位置就全变成 0，而每一列仍然保持归一化。 |

| Now, there are versions of attention mechanisms where masking isn't always applied. | The masking process is done to prevent later tokens from influencing earlier tokens, as the later tokens could give away the word that comes next. | 做掩码处理，是为了防止后面的 token 影响前面的 token，因为后面的 token 可能把下一个词的答案泄露出去。 |
| Another fact that's worth reflecting on is how the size of this attention pattern is equal to the _square_ of the context size. | 另一个值得回味的事实是：注意力模式的尺寸，等于上下文长度的_平方_。 |
| One row and one column for each token. | 每个 token 各占一行、一列。 |
| This is why context size could act as a significant limitation for large language models and why scaling it up is nontrivial. | 这就是为什么上下文长度可能成为大语言模型的一大限制，也是为什么想把它做大绝非易事。 |
| Of course, motivated by a desire for larger context windows, in recent years we have seen some variations to the attention mechanism that are aimed at making context more scalable, but for now, all we're focused on are the basics. | 当然，在扩大上下文窗口的愿望驱动下，近年来也出现了一些旨在让上下文更可扩展的注意力机制变体；但眼下我们要关注的，仍是最基础的那些。 |

## 值矩阵与嵌入更新（Values & Embedding Updates）

| 原文 | 译文 |

| Once you have this attention pattern describing which words are relevant to updating which other words, the next step is to actually update those embeddings. | 有了这张描述「哪个词与更新哪个词相关」的注意力模式之后，下一步就是真正去更新那些嵌入。 |
| For example, we would want the embedding of _fluffy_ to somehow cause a change to the embedding of _creature_, one that moves it to a different part of this high-dimensional embedding space that more specifically encodes a _fluffy creature_. | 比如，我们希望 _fluffy_ 的嵌入能以某种方式引发 _creature_ 嵌入的改变——把它挪到这个高维嵌入空间中另一片区域，那里更精确地编码着「毛茸茸的生物」。 |
| The most straightforward way would be to use a third matrix, what we call the **value matrix**. In true multi-headed attention, this matrix is factored into two parts, but for the moment, it's easiest to think of as just one operation. | 最直截了当的办法，是启用第三个矩阵，也就是我们所说的**值矩阵（value matrix）**。在真正的多头注意力里，这个矩阵会分解成两部分；不过眼下，把它当成一步运算来想最省事。 |
| We would multiply this value matrix by the embedding of that first word, for example _fluffy_. We'll denote this value matrix as $W_V$. | 我们会把这个值矩阵乘以第一个词——比如 _fluffy_——的嵌入。我们把这个值矩阵记作 $W_V$。 |
| The result of this is what we would call a value vector, and this is something that we would add to the embedding of the second word. In our case, this value vector is something we would add to the embedding of _creature_ to move it to a different part of the dimensional embedding space that encodes a _fluffy creature_. | 相乘的结果，就是我们所说的值向量（value vector），我们要把它加到第二个词的嵌入上。在我们的例子里，这个值向量要加到 _creature_ 的嵌入上，把它挪到嵌入空间中编码「毛茸茸的生物」的另一片区域。 |
| This value vector lives in the same very high-dimensional space as the embeddings, and when the value matrix is multiplied by a word's embedding, we can think of it effectively answering the question: | 这个值向量与嵌入同处一个非常高维的空间；当值矩阵乘以某个词的嵌入时，我们可以认为它实际上在回答这样一个问题： |
| _If this word is relevant to adjusting the meaning of another word, what specific adjustments should be made to the other word's embedding to reflect this relevance accurately?_ | _如果这个词与调整另一个词的含义有关，那么应该对另一个词的嵌入做哪些具体调整，才能准确体现这种相关性？_ |

| Under the embedding of Creature, we would be adding large proportions of the value vectors for _fluffy_ and _blue_, while all of the other value vectors get nearly zeroed out. | 在 Creature 这一列下面，我们会大比例地加入 _fluffy_ 和 _blue_ 的值向量，而其余所有值向量几乎都被清零。 |

| In Linear Algebra terms, what we're essentially doing is constraining the overall value map to be a _low-rank transformation_. | 用线性代数的话说，我们本质上是在约束整个值映射，让它成为一个_低秩变换_（low-rank transformation）。 |

## 多头注意力（Multi-headed Attention）

| 原文 | 译文 |
|---|---|
| All the content we've covered so far is all contained in a single head of attention. A full attention block consists of what's called a multi-headed attention, where a lot of these operations are run in parallel, each with its own distinct key, query, and value maps. | 到目前为止讲的所有内容，都还只装在一个单头注意力里。一个完整的注意力块，由所谓的多头注意力（multi-headed attention）构成：许多这样的运算并行展开，各自拥有一套不同的键、查询、值映射。 |
| GPT-3, for example, uses 96 attention heads inside each block. Just to spell it all out very explicitly, this means you have 96 distinct key and query matrices producing 96 distinct attention patterns. Then each head has its own distinct value matrices used to produce 96 sequences of value vectors. These value vectors are then all added together using the corresponding attention patterns as weights. | 以 GPT-3 为例，每个块里有 96 个注意力头。把话说得再明白不过：这意味着你有 96 套不同的键、查询矩阵，产出 96 张不同的注意力模式；然后每个头又有自己一套不同的值矩阵，用来产出 96 组值向量序列。这些值向量最后再以相应的注意力模式为权重，全部加在一起。 |
| What this means is that for each token, or position in the context, every one of these heads produces a proposed change, labeled as $\Delta \vec{E}$, to be added to the embedding in that position. Then, all of these proposed changes would be added up, one for each head, and the result is added to the original embedding of that position. | 这意味着：对每个 token——也就是上下文中的每个位置——每个头都会产出一笔提议的改动，记作 $\Delta \vec{E}$，准备加到该位置的嵌入上。随后，这些提议的改动（每个头一笔）全部加总，其结果再加到该位置的原始嵌入上。 |
| This entire sum would be one _slice_ of what's outputted from this multi-headed attention block; a single one of those refined embeddings that pops out the other end of it. | 这一整个总和，就是这个多头注意力块输出里的_一片_——从它另一头蹦出来的那些精炼嵌入中的一员。 |
| Again, this is a lot to think about, so don't worry at all if it takes some time to sink in. The overall idea is that by running many distinct heads in parallel, the model is given the capacity to learn many distinct ways that context changes meaning. | 再说一遍，这里的信息量确实很大，一时消化不了完全不必焦虑。总体思想是：让许多不同的头并行运转，模型便获得了学习「上下文改变含义的种种不同方式」的能力。 |

> - **spell out** —— 一五一十讲明。spell it all out very explicitly＝把一切都挑明。
