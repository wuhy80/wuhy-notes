Yes, you can enable a firewall on machines running Kubernetes (K8S), but you need to ensure that essential ports are open to allow Kubernetes components to communicate properly. The specific ports you need to open will depend on your cluster configuration and the services you are running. Here’s a comprehensive list of the ports typically required for a Kubernetes cluster to function:

### Ports to Open for Kubernetes

#### 1. **Control Plane (Master Nodes)**

- **API Server** (TCP 6443): Kubernetes API server
  ```bash
  sudo iptables -A INPUT -p tcp --dport 6443 -j ACCEPT
  ```

- **etcd** (TCP 2379-2380): etcd server client API
  ```bash
  sudo iptables -A INPUT -p tcp --dport 2379 -j ACCEPT
  sudo iptables -A INPUT -p tcp --dport 2380 -j ACCEPT
  ```

- **Kubelet** (TCP 10250): Kubelet API
  ```bash
  sudo iptables -A INPUT -p tcp --dport 10250 -j ACCEPT
  ```

- **Kube-scheduler** (TCP 10251): Kube-scheduler
  ```bash
  sudo iptables -A INPUT -p tcp --dport 10251 -j ACCEPT
  ```

- **Kube-controller-manager** (TCP 10252): Kube-controller-manager
  ```bash
  sudo iptables -A INPUT -p tcp --dport 10252 -j ACCEPT
  ```

#### 2. **Worker Nodes**

- **Kubelet** (TCP 10250): Kubelet API
  ```bash
  sudo iptables -A INPUT -p tcp --dport 10250 -j ACCEPT
  ```

- **NodePort Services** (TCP 30000-32767): NodePort range for services
  ```bash
  sudo iptables -A INPUT -p tcp --dport 30000:32767 -j ACCEPT
  ```

#### 3. **Network Plugins (CNI)**

The ports required for CNI plugins like Calico, Flannel, Weave, etc., may vary. Here are some common examples:

- **Calico**:
  - TCP 179 (BGP)
    ```bash
    sudo iptables -A INPUT -p tcp --dport 179 -j ACCEPT
    ```

- **Flannel**:
  - UDP 8472 (VXLAN)
    ```bash
    sudo iptables -A INPUT -p udp --dport 8472 -j ACCEPT
    ```

- **Weave**:
  - TCP/UDP 6783-6784 (Weave Net)
    ```bash
    sudo iptables -A INPUT -p tcp --dport 6783 -j ACCEPT
    sudo iptables -A INPUT -p udp --dport 6783 -j ACCEPT
    sudo iptables -A INPUT -p tcp --dport 6784 -j ACCEPT
    sudo iptables -A INPUT -p udp --dport 6784 -j ACCEPT
    ```

#### 4. **Ingress Controllers**

If you are using an ingress controller like Nginx, you will need to open the ports it uses (usually 80 and 443).

- **HTTP** (TCP 80): Ingress controller
  ```bash
  sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
  ```

- **HTTPS** (TCP 443): Ingress controller
  ```bash
  sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
  ```

### Example UFW Configuration

If you are using UFW on Ubuntu, here is an example configuration to allow necessary ports:

```bash
sudo ufw allow 6443/tcp
sudo ufw allow 2379:2380/tcp
sudo ufw allow 10250/tcp
sudo ufw allow 10251/tcp
sudo ufw allow 10252/tcp
sudo ufw allow 30000:32767/tcp

# Network plugin ports
sudo ufw allow 8472/udp  # For Flannel
sudo ufw allow 179/tcp   # For Calico
sudo ufw allow 6783:6784/tcp  # For Weave
sudo ufw allow 6783:6784/udp  # For Weave

# Ingress ports
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Enable UFW
sudo ufw enable
```

### Example iptables Configuration

Here is an example using iptables:

```bash
# Control Plane
sudo iptables -A INPUT -p tcp --dport 6443 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 2379 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 2380 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 10250 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 10251 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 10252 -j ACCEPT

# Worker Nodes
sudo iptables -A INPUT -p tcp --dport 10250 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 30000:32767 -j ACCEPT

# Network Plugins (example for Flannel)
sudo iptables -A INPUT -p udp --dport 8472 -j ACCEPT

# Ingress Controllers
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Save iptables rules
sudo iptables-save > /etc/iptables/rules.v4
```

### Conclusion

Enabling a firewall on Kubernetes nodes is possible and advisable for security reasons. However, you must ensure that all necessary ports are open for Kubernetes components to communicate effectively. The specific ports to open depend on your Kubernetes setup and the additional services and plugins you are using. The examples above provide a good starting point for configuring firewall rules using both `iptables` and `ufw`.
