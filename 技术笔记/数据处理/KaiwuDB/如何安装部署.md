# KaiwuDB 安装部署检查清单

> [!warning] 版本与授权
> KaiwuDB 的安装包、许可证、端口和初始化参数随版本及部署形态变化。下面是部署前后的通用检查清单，不替代对应版本的官方安装手册；实际命令应以交付包中的 `README`、`install.sh` 或 Helm Chart 为准。

## 部署前准备

- [ ] 固定 KaiwuDB 版本、部署形态（单机、集群或 Kubernetes）和许可证文件来源。
- [ ] 确认操作系统、CPU 架构、内核参数、文件描述符上限、时区和 NTP/chrony 已满足要求。
- [ ] 为数据目录、WAL/日志目录和备份目录准备独立磁盘，并确认属主、权限和剩余空间。
- [ ] 规划节点 IP、节点名称、客户端端口、内部通信端口和防火墙来源网段；不要直接开放到公网。
- [ ] 准备专用运行用户、最小权限账号、TLS 证书和密码存储位置，不把凭据写进 Git 或命令历史。

## 安装与初始化

1. 校验安装包签名或校验和，解压到版本化目录，避免覆盖正在运行的版本。
2. 按官方示例生成配置文件，明确数据目录、日志级别、监听地址、认证和连接池参数。
3. 以专用用户启动服务，先检查日志和监听端口，再执行初始化 SQL 或集群引导命令。
4. 集群部署时逐节点加入并验证成员状态、时间同步、复制/共识状态和故障转移行为；不要只以进程存活判断部署成功。

## 验证与运维

```bash
# 以下命令仅为通用检查，具体服务名和端口以版本文档为准
systemctl status <kaiwudb-service>
ss -lntp | grep -i kaiwu
df -h <data-dir> <backup-dir>
```

- 使用只读测试连接验证认证、字符集、时区和基本 SQL 能力。
- 建立慢查询、连接数、事务延迟、磁盘使用率和复制延迟监控。
- 在投入生产前完成一次全量备份和恢复演练，记录恢复时间和数据校验结果。
- 升级前阅读版本兼容矩阵，备份配置和元数据，并先在隔离环境执行回滚演练。
