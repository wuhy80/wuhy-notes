# 知识库双仓库拆分与多机同步

> [!summary] 一句话
> 2026-10-01 把原知识库拆成两个**独立且都私有**的 git 仓库：**主库**（技术/学习/项目）与**私密库**（私密资料 + 日记 + 任务），并用 `git filter-repo` 把私密路径从主库历史中彻底剥离。两边各自独立备份。

## 一、拆分结果

| 仓库 | 路径 | 内容 |
|---|---|---|
| **主库** | `E:\Obsidian\wuhy80_new` | 技术笔记、大模型、读书笔记、极客时间、编程语言、专项项目（不含客户档案）等 |
| **私密库** | `E:\Obsidian\wuhy80_private` | 我的日记、个人信息、投资管理、专项项目/客户档案信息、任务管理、Inbox、网址收藏/账号信息.md |
| **回退镜像** | `E:\Obsidian\_backup_vault_before_split.git` | 拆分前的完整镜像（1218 提交 / 256.6 MB），出问题可从它恢复 |

| 指标 | 主库 | 私密库 |
|---|---|---|
| 提交数 | 603（拆分前 1218） | 864 |
| 跟踪文件 | 833（拆分前 1371） | 550 |

剥离后主库历史中**已检索不到**任何私密路径（`git log --all -- <路径>` 全部为空）。

## 二、私密库的约定

- 私密库是**独立的 Obsidian vault**：在 Obsidian 里「打开文件夹作为库」选 `E:\Obsidian\wuhy80_private`
- 已复制 `.obsidian/`（25 个插件）与 `template/`（含日志、周报、月报、年报模板），**日记工作流开箱可用**：Daily Notes、Periodic Notes、Templater 的路径均验证可解析
- `.obsidian/` **不纳入版本控制**（与主库策略一致，避免插件内的密钥进入仓库）
- 日记、周报、月报、年报都在这个库里，相对路径与拆分前完全一致

## 三、日常备份

两个库各自独立提交与推送：

```bash
# 主库 → 自建 Gitea（国内直连，快）
cd E:\Obsidian\wuhy80_new
git add -A && git commit -m "自动备份: <时间戳>"
git push origin master

# 私密库 → GitHub 私有仓库
cd E:\Obsidian\wuhy80_private
git add -A && git commit -m "私密备份: <时间戳>"
git push origin master
```

## 四、推送到 GitHub（本机网络注意）

本机访问 GitHub 的特点（实测）：

- `github.com` 的 HTTPS **时通时断**（曾连续 3 次 21 秒超时）
- `raw.githubusercontent.com` **被重置**，下载 raw/zip 需走 `gh-proxy.com` 之类的加速前缀
- **SSH 稳定可用**（22 和 443 都通），已配置走 443：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile C:\Users\Administrator\.ssh\id_ed25519
  IdentitiesOnly yes
  ServerAliveInterval 30
  ServerAliveCountMax 6
```

两个目标仓库首次推送时远端只有一条无关的「初始化」提交，因此需要 `--force`：

```bash
git push --force github master:main
```

主库体积 243 MB，链路抖动时用**分段推送**降低重试成本：先推一个较早的提交，再推最新（后续都是增量）。

## 五、家里那台机器的对齐（关键步骤）

> [!danger] 顺序绝对不能颠倒
> 主库历史已被改写。家里那台如果直接 `git fetch && git reset --hard`，会**把工作区里的私密文件一并删掉**（因为它们在旧历史里被跟踪，在新历史里不存在）。

1. **先在家里那台**把私密内容整体复制出去（U 盘、网盘或任意临时目录）：
   - `我的日记/`、`个人信息/`、`投资管理/`、`专项项目/客户档案信息/`、`任务管理/`、`Inbox/`、`网址收藏/账号信息.md`
2. 复制完成并确认无误后，再对齐主库：
   ```bash
   cd <主库路径>
   git fetch origin
   git reset --hard origin/master
   ```
3. 把第 1 步复制出来的私密内容，放进家里那台的**私密库**目录（`git clone` 出来的 `wuhy80_private`），逐项比对确认后提交
4. 检查家里那台的 obsidian-git 插件，确认它的提交/推送目标仍然是主库，且没有把私密目录当成主库的一部分

## 六、其他遗留事项

- 主库的 `.obsidian/daily-notes.json` 与 `periodic-notes/data.json` **仍指向 `我的日记/`**。在主库按 `Ctrl+D` 会重新创建该目录，而它已被 `.gitignore` 排除——**会被静默地排除在备份之外**。日记请一律在私密库里记录。
- 主库 `.gitignore` 中保留着私密路径的排除规则。目录虽已不存在，但规则留下可作保险：万一将来误建同名目录，不会被提交。
- Gitea（`origin`）里的主库仍是改写前的历史，需要 `--force` 覆盖，或将其保留为归档、不再推送。
