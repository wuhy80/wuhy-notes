# API 技术对比分析

## 1. REST API vs GraphQL 核心对比

### 1.1 数据获取方式对比

**REST API:**
```http
# 需要多个端点
GET /api/users/123        # 获取用户信息
GET /api/users/123/posts  # 获取用户的文章
GET /api/users/123/followers # 获取用户的关注者
```

**GraphQL:**
```graphql
# 单个查询获取所有需要的数据
query {
  user(id: "123") {
    name
    email
    posts {
      title
      content
    }
    followers {
      name
    }
  }
}
```

### 1.2 主要区别

| 特性 | REST API | GraphQL |
|------|-----------|----------|
| 端点数量 | 多个端点 | 通常单个端点 |
| 数据获取 | 固定响应结构 | 灵活请求所需字段 |
| 版本控制 | 通常通过 URL(v1/v2) 或请求头 | 通过字段弃用和 schema 演进，仍可能需要版本或兼容策略 |
| 缓存机制 | HTTP 原生缓存 | 需要自定义缓存策略 |
| 文件上传 | 简单直接 | 需要额外规范 |
| 错误处理 | HTTP 状态码 | 自定义错误结构 |
| 学习曲线 | 相对简单 | 相对较陡 |

## 2. gRPC

### 2.1 特点
- 基于 HTTP/2
- 使用 Protocol Buffers
- 支持双向流式传输
- 性能极高

### 2.2 示例代码

```protobuf
// 定义服务
service UserService {
  rpc GetUser (UserRequest) returns (UserResponse) {}
  rpc StreamUpdates (UserRequest) returns (stream UserUpdate) {}
}

message UserRequest {
  string user_id = 1;
}

message UserResponse {
  string name = 1;
  string email = 2;
}
```

### 2.3 适用场景
- 微服务之间的通信
- 需要高性能的实时通信
- 资源受限的环境（移动网络）

## 3. SOAP

### 3.1 特点
- 使用 XML 格式
- 严格的标准
- 可结合 WS-Security、TLS 等企业规范（安全能力并非 SOAP 协议本身自动提供）
- 企业级特性支持

### 3.2 示例代码

```xml
<?xml version="1.0"?>
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope">
  <soap:Header>
  </soap:Header>
  <soap:Body>
    <m:GetUser xmlns:m="http://www.example.org/user">
      <m:UserId>123</m:UserId>
    </m:GetUser>
  </soap:Body>
</soap:Envelope>
```

### 3.3 适用场景
- 企业级应用
- 需要严格安全标准的场景
- 传统企业集成

## 4. WebSocket

### 4.1 特点
- 全双工通信
- 持久连接
- 实时数据传输
- 较低的延迟

### 4.2 示例代码

```javascript
// 服务端
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', function connection(ws) {
  ws.on('message', function incoming(message) {
    console.log('received: %s', message);
  });
  ws.send('something');
});

// 客户端
const ws = new WebSocket('ws://localhost:8080');
ws.onmessage = function(event) {
  console.log('received:', event.data);
};
```

### 4.3 适用场景
- 实时应用（聊天、游戏）
- 需要服务器推送的场景
- 低延迟要求的应用

## 5. 技术选择建议

### 5.1 选择 REST API 的场景
- 构建公共 API
- 简单的 CRUD 操作
- 需要利用 HTTP 缓存
- 资源导向的 API 设计

### 5.2 选择 GraphQL 的场景
- 复杂的数据关系
- 需要灵活的数据查询
- 移动应用 API
- 聚合多个服务的数据

### 5.3 选择 gRPC 的场景
- 微服务架构内部通信
- 需要极高性能
- 服务间流式数据传输
- 多语言服务集成

### 5.4 选择 WebSocket 的场景
- 实时数据更新
- 双向通信需求
- 聊天应用
- 实时监控
