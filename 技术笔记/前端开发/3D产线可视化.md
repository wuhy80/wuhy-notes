## 六个关键技术点

### 1. 程序化建模：没有模型文件也能像样

机器不是 GLB，是 `box()` / `cyl()` 拼的组合体。一个工位 20~40 个 mesh，全场景约 400 个，桌面端稳定 60fps。

这么做的理由很实际：**不需要建模师**。布局和造型一天能出片；代价是只能"形似"，近看没有螺丝和开孔。

```js
function box(w, h, d, mat, x = 0, y = 0, z = 0) {
  const m = new THREE.Mesh(new THREE.BoxGeometry(w, h, d), mat);
  m.position.set(x, y, z);
  m.castShadow = m.receiveShadow = true;
  return m;
}
```

### 2. 泛光：工业风的灵魂，但阈值才是关键

`UnrealBloomPass` 让自发光超过阈值才晕开——灯带、警示灯、屏幕发亮，普通金属面料不发光。阈值调低了整屏发灰，调高了没味道。

```js
const composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera));
composer.addPass(new UnrealBloomPass(new THREE.Vector2(w, h), 0.42, 0.48, 0.95));
composer.addPass(new OutputPass());   // 负责色调映射与色彩空间
```

- 强度 `0.42`、半径 `0.48`、**阈值 `0.95`**
- 用了 composer 就删掉 `renderer.render()`，改 `composer.render()`

### 3. 环境反射：最容易踩的坑

**`metalness` 高的材质没有 `scene.environment` 会渲染成一团黑**，看起来像"没打光"。我卡在这一步最久：明明加了 2.6 强度的平行光，机器还是黑块。原因是金属材质的颜色主要来自环境反射，直接光几乎不贡献。

```js
const pmrem = new THREE.PMREMGenerator(renderer);
scene.environment = pmrem.fromScene(new RoomEnvironment(), 0.04).texture;
scene.environmentIntensity = 0.22;   // 太低没质感，太高整个场景发灰
```

### 4. HUD 用 DOM，不要画进 3D

KPI 卡、工位列表、事件流都是普通 HTML/CSS 叠在 canvas 上：字体清晰、改文案不用重建、可被读屏，还能直接用 CSS 做呼吸灯和角标。

```css
#hud { position: fixed; inset: 0; pointer-events: none; z-index: 10; }
#hud button, #hud .panel { pointer-events: auto; }  /* 否则挡住旋转拖拽 */
```

### 5. 拾取：Raycaster + userData 冒泡

给工位组和地面光圈都打上 `userData.stationId`，射线打到哪个子 mesh 都往上冒泡找工位。

```js
function stationOf(obj) {
  for (let o = obj; o; o = o.parent) {
    if (o.userData?.stationId) return o.userData.stationId;
  }
  return null;
}
```

悬停出 tooltip，点击选中并推近相机；右侧列表点哪跳哪，状态改颜色时同步改地面光圈（`LineBasicMaterial.color`）。

### 6. 相机：缓动比瞬移重要

三段逻辑：`camGoal` 做指数缓动推近某个工位、`tourOn` 沿产线缓慢 dolly 巡游、用户一拖就退出巡游。

```js
if (tourOn) {
  tourT += dt;
  const p = (tourT % 54) / 54;
  const back = p < 0.5 ? p * 2 : (1 - p) * 2;      // 往返
  const x = THREE.MathUtils.lerp(-42, 42, back);
  const k = 1 - Math.pow(0.0016, dt);              // 与帧率无关的平滑
  camera.position.lerp(new THREE.Vector3(x + 17, 13.5, 24.5), k);
  controls.target.lerp(new THREE.Vector3(x, 2.8, 0), k);
}
```

## 接真实数据只改数据层

当前 KPI 和工位状态是前端模拟的。接 MES / SCADA 时，其余逻辑一行不用动：

```js
setInterval(async () => {
  const d = await (await fetch("/api/line")).json();
  stats.prod = d.output;
  stats.yield = d.yield;
  stats.oee = d.oee;
  d.stations.forEach((s) => {
    const st = STATIONS.find((x) => x.id === s.id);
    if (st) setStationStatus(st, s.status);   // 状态点 + 地面光圈 + N/8 计数
  });
}, 2000);
```

## 换成自己的产线

1. `STATIONS` 数组：工位 id / 名称 / 英文名 / X 坐标 / 节拍。
2. 对应的 `build*()` 函数：机器长什么样。汽车焊装、锂电叠片、食品灌装，都是"箱子 + 机械臂 + 传送带"的不同组合。
3. `EVENT_POOL` 和 KPI 字段：换成行业话术（焊点合格率、CT、OEE）。

配色在 `style.css` 的 `:root`（`--cyan` / `--amber` / `--red`）和 `app.js` 的 `M` 材质表。

## 想 1:1 复刻真实车间

程序化箱子拼的是"形似"。要做到现场照片那种可信度：

1. Blender 按现场照片/图纸建模，导出 **GLB**（10~30 万面，开 Draco 压缩）。
2. `GLTFLoader` + `DRACOLoader` 替换对应 `build*()`，保留 `userData.stationId`。
3. 相机、灯光、HUD 全部不用改。

布局和 HUD 约一天；8 台设备的像样模型，一两周。

## 踩坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开白屏 | `file://` 下 ES Module 被拦 | 必须起 http 服务（`python -m http.server`） |
| 金属全黑 | 缺 `scene.environment` | PMREM + `environmentIntensity` 0.2 左右 |
| 整屏发灰 / 糊 | 泛光阈值过低 | 阈值提到 0.9 以上，只让自发光过线 |
| 地面条状阴影 | 阴影相机范围过大 | 收紧 shadow camera，`normalBias ≈ 0.03` |
| 拖不动视角 | HUD 容器挡住了 canvas | 容器 `pointer-events:none`，控件单独 `auto` |
| 标签文字糊 | 贴图字号相对平面过大 | 平面与 canvas 尺寸按 1:1 折算字号 |
