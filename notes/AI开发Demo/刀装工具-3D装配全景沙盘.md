# 刀装工具 · 3D 装配全景沙盘

> [!summary] 一句话
> 把「刀柄 → 夹持 → 刀具 → 工装 → 量测」这套装夹关系，做成一个能悬停看关系、能按步走流程的单文件 3D 沙盘。
> 34 个节点 / 45 条关系 / 5 个分区 / 4 个层级 / 4 套装刀推演，**双击 HTML 就能跑**。

<img class="site-img" src="ai开发demo/刀装工具-总览.jpg" alt="刀装工具-总览.jpg">


## 一、它解决什么问题

装刀这件事，知识散在三处：图纸上的配合关系、工艺卡上的拧紧扭矩、老师傅嘴里的「这里要清干净」。
沙盘把它们压进同一张图：

- **竖直方向**是抽象层级：`L1 物理装配 → L2 规格约束 → L3 作业记录 → L4 计算与放行`
- **水平方向**是五个装配分区：主轴接口 / 刀柄本体 / 夹持单元 / 装刀工装 / 预调量测
- 谁夹着谁、谁约束谁、哪一步生成哪张记录，全在图上的连线上

## 二、交互设计

| 操作 | 行为 |
| --- | --- |
| **悬浮** | 亮出该零件的全部连线 + 相邻对象名称 + 关系动词 + 规格浮卡；其余节点压暗 |
| **悬浮分色** | 上游（谁供给我/约束我）青 `#38bdf8` ▲；下游（我供给谁/对谁施力）橙 `#fb923c` ▼ |
| **点击** | 钉住选中，右侧「装配视检」抽屉显示规格、工艺要点、上下游关系 |

| **拖拽 / 滚轮** | 旋转 / 缩放 |
| **推演** | 四个装刀场景，逐步播放（2.6s/步，可暂停、上一步/下一步，`←/→` 单步、`Space` 播放） |
| **四视图** | 3D 装配沙盘 / 接口规格矩阵 / 装刀作业 SOP / 零部件索引 |

## 三、实现拆解

### 1. 手写透视投影（不用 three.js）

```js
const x1 = dx * cosY + dz * sinY;
const z1 = -dx * sinY + dz * cosY;
const y2 = dy * cosP - z1 * sinP;
const z2 = dy * sinP + z1 * cosP;
const scale = (FOV * zoom) / Math.max(180, CAM_DIST - z2);
return { sx: cx + x1 * scale, sy: cy - y2 * scale, z2, scale, depth };
```

只做「结构示意」时，这套比引入 3D 引擎轻得多；节点、连线、标签全是 2D 绘制，文字永远清晰。

### 2. 分层平板 + 分区底板

每层画一块带厚度的平板（顶面渐变 + 侧壁 + 前沿发光 + 四角刻度），层内按分区画**世界坐标圆角矩形**（投影后再描边，透视下依然是圆角），配合呼吸虚线。

### 3. 悬浮方向分色

```js
function getDirectionMap(focusId) {
  const map = new Map();
  LINK_INDEX.get(focusId).forEach(({ link }) => {
    const other = link.from === focusId ? link.to : link.from;
    const dir = link.from === focusId ? 'down' : 'up';   // from=我 → 下游
    const cur = map.get(other);
    if (!cur) map.set(other, dir);
    else if (cur !== dir) map.set(other, 'both');
  });
  return map;
}
```

同一份结果用在四处：连线渐变染色、节点外环、名字胶囊边框 + ▲/▼ 小箭头、浮卡底部「上游 n / 下游 m」。

### 4. 装刀推演的步骤集合

```js
function computeScenarioSets() {
  frameStepNodes = new Set(); frameStepEdges = new Set();
  frameDoneNodes = new Set(); frameDoneEdges = new Set();
  const steps = SCENARIOS[state.activeScenario].stepsList;
  const cur = state.scenarioStep;
  steps.forEach((st, k) => {
    if (k > cur) return;
    const nodes = k === cur ? frameStepNodes : frameDoneNodes;
    const edges = k === cur ? frameStepEdges : frameDoneEdges;
    st.nodes.forEach(id => nodes.add(id));
    st.edges.forEach(([a, b]) => edges.add(a + '>' + b));
  });
}
```

渲染时按集合压暗：**当前步 1.0 / 已完成 0.6 / 未到 0.11**，讲解节奏就出来了。

### 5. 标签落位队列（画面不糊的关键）

节点名、关系动词、悬浮浮卡全部进同一个候选队列，按优先级排序（悬浮 100 > 选中 95 > 当前步 88 > 邻居 70 > 普通 10），逐个做矩形碰撞检测，撞了就跳过。**名字优先于动词**：宁可少一个「夹持立铣刀」，也不让动词压住对象名。

### 6. 两个容易踩的坑

- **浅色主题下阴影变灰墙**：平板的地面投影 `rgba(0,0,0,.30)` 在浅色底上非常脏，要按主题降到 0.045。
- **自动播放别用帧计数**：`timer += 1/60` 在低帧率机器上会慢一半，改用 `performance.now()` 判 2.6s。

## 四、数据模型

| 维度 | 内容 |
| --- | --- |
| 分区（5） | `SPINDLE` 主轴接口 / `HOLDER` 刀柄本体 / `CLAMP` 夹持单元 / `SETUP` 装刀工装 / `METRO` 预调量测 |
| 层级（4） | `L1` 物理装配 / `L2` 规格约束 / `L3` 装刀作业 / `L4` 计算与放行 |
| 节点类型 | 实体（圆）· 规格（菱形）· 记录（圆角方）· 计算/动作（六边形） |
| 节点字段 | `id / label / code / scope / layer / archetype / pos / spec / params / note / tags` |
| 关系字段 | `from / to / rel`（动词，如「螺纹连接」「约束扭矩」「热套夹持」） |

节点高度由所属层自动推导，改层间距不用动数据。

## 六、取舍与待办

- 只有 3D 示意，没有真实刀具模型（导入 glTF 会破坏「单文件」的约束）。
- 规格数据是 BT/HSK 通用示例，可整体替换成真实刀具库 / 工艺规范。
- 待办：导出「装刀工序卡」打印版；每步补判定标准（如「跳动 ≤0.005 才算过」）；接 ERP 刀具主数据。

## 七、可复用的三条

1. **结构示意图别上 3D 引擎**：手写投影 + 2D 绘制，体积、性能、文字清晰度都更好。
2. **悬浮优先**：先让人「划过去就懂」，再教他点击；演示效率差很多。
3. **标签要有仲裁**：同屏几十个标签，没有优先级和碰撞检测必然糊。
