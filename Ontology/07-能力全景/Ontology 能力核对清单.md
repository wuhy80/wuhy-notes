# Ontology 能力核对清单

> [!summary] 用途
> 把 [[Ontology/07-能力全景/Palantir Ontology 能力全景|能力全景]] 里的 79 项能力压成一张可打分的表。做自研评估时，每行按 **0 = 未具备 / 1 = 部分具备 / 2 = 具备** 打分，再按域汇总，短板会立刻显现。

## 怎么用

1. 先看「初步判断」列。它只是根据常见自研路径给的默认建议，不是结论，可以整列改掉。
2. 对每行打分，并把证据写在「现状 / 备注」列（已有系统、开源组件、计划）。
3. 按域求平均：低于 1.0 的域就是近期要补的；P0 项为 0 的域优先处理。
4. 不要追求满分。Palantir 自己也把一部分能力标成 Beta 或分场景支持。

## 三个必须先回答的问题

> [!question] 打分之前先定这三件事
> 1. **对象的写入路径是什么？** 只有只读对象、没有受控写回，本质上还是知识图谱/BI，不是 Ontology。
> 2. **权限在哪一层生效？** 如果行/列过滤只做在应用层，导出和 Agent 输出就是天然缺口。
> 3. **谁能改模型？** 没有分支与评审，对象类型会随着业务扩张变成没人敢碰的遗留资产。
