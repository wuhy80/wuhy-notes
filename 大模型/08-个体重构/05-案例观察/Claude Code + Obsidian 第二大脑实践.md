# Claude Code + Obsidian 第二大脑实践

> [!summary] 案例定位
> 这是一篇从“工具介绍”视角迁移到“个体重构案例”视角的整理笔记，用来说明 AI 如何真正进入个人知识系统与工作流，而不是只停留在聊天窗口里。

## 为什么这个案例值得放在这里

这类实践覆盖了个体重构里的几个关键问题：

- 人如何把 AI 接入自己的长期知识库
- 笔记系统如何从“存储工具”变成“协作系统”
- 工作流如何从手工整理转向 AI 参与整理、分析和执行
- 本地知识库如何成为个人上下文资产

## 这个案例体现出的关键变化

### 1. 知识库从“给自己看”变成“给人和 AI 共同使用”

一旦 Claude Code 能直接读取整个库，笔记的价值就不只是归档，而是：

- 检索上下文
- 汇总历史记录
- 生成结构化输出
- 参与持续整理

### 2. AI 的核心价值不只在写作，更在阅读

原笔记里一个很重要的点是：AI 不只是帮你写，而是帮你读、帮你找、帮你梳理。

这意味着高价值场景会集中在：

- 大量历史资料回顾
- 多篇笔记关联分析
- 从碎片里提炼主题
- 对项目、日志和知识进行结构化回顾

### 3. 本地知识库天然适合沉淀个人上下文

与云端聊天相比，Obsidian + Claude Code 更适合承接：

- 私密资料
- 长周期项目
- 个人表达风格
- 已有知识结构

## 可复用的方法

### 方法一：把 AI 当“整理与分析层”

适合：

- 处理 Inbox
- 整理会议记录
- 生成阶段性总结
- 补充内部链接

### 方法二：把知识库当“上下文仓库”

适合：

- 写方案前先拉取既有资料
- 写周报前汇总一周记录
- 做复盘时关联项目、日志和摘录

### 方法三：把高频动作逐步模板化

适合沉淀为：

- 指令模板
- 输出模板
- 结构化检查清单
