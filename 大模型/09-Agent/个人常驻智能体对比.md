# 个人常驻智能体对比

> [!summary] 定位
> 本文只比较类似 [[Hermes]]、[[OpenClaw]] 这一类“能长期运行、接工具、接账号、执行任务”的智能体产品或运行时，不比较纯 SDK 框架。纯框架看 [[Agent框架选型对比]]。

## 一、这一类和普通 Agent 框架有什么区别

普通 Agent 框架解决的是“怎么开发一个 Agent”。

个人常驻智能体 / 数字员工解决的是“怎么运行一个能替你干活的 Agent”。

它们通常具备：

- 长期运行
- 任务队列
- 记忆或上下文沉淀
- 工具、账号、浏览器、文件系统接入
- 聊天、浏览器、桌面或工作流平台入口
- 人工确认、审计、回放或任务日志

## 三、按使用场景选

### 个人本地自动化

优先看：

1. [[OpenClaw]]
2. [[Agent Zero]]
3. [[Letta]]

适合关心本地运行、个人上下文、长期记忆和技能沉淀的人。

### 浏览器和网页自动化

优先看：

1. [[Fellou]]
2. [[Manus]]
3. [[Genspark]]

适合需要跨网页搜索、表单、账号、报告和资料整理的人。

### 软件开发智能体

优先看：

1. [[OpenHands]]
2. [[Agent Zero]]
3. [[AutoGPT Platform]]

适合代码、终端、浏览器、仓库、PR、测试和自动化工程任务。

### 企业数字员工

优先看：

1. [[Relevance AI]]
2. [[Lindy]]
3. [[AutoGPT Platform]]

适合 CRM、邮件、销售、客服、招聘、运营等有明确业务流程和审计要求的团队。

## 四、我对这一类的判断

> [!warning] 核心判断
> 这一类系统的关键不只是“能不能完成任务”，而是“能不能被安全地赋权”。一旦它能读邮箱、点网页、改文件、发消息、连 CRM，它就应该按半个员工来治理。

重点看：

- 是否有权限分级
- 是否有操作前确认
- 是否有审计日志
- 是否有任务回放
- 是否支持撤销或回滚
- 是否能隔离不同项目上下文
- 是否能限制技能和插件权限
- 是否能处理 prompt injection 和网页污染

## 五、和普通 Agent 框架的组合

这些产品/运行时不一定替代 [[LangGraph]]、[[AutoGen]]、[[OpenAI Agents SDK]]。

更合理的关系是：

- 运行时 / 产品层：[[OpenClaw]]、[[Agent Zero]]、[[Manus]]、[[Fellou]]
- 编排层：[[LangGraph]]、[[AutoGen]]、[[OpenAI Agents SDK]]
- 工具协议层：[[大模型/02-应用开发/MCP/MCP概览|MCP]]
- 记忆层：[[Letta]]
- 企业治理层：[[Relevance AI]]
