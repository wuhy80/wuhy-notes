# Grokking：过拟合之后，模型为什么突然学会了

> [!summary] 一句话版本
> 小模型在小算法任务上会先「背题」：训练集很快 100%，验证集长期等于随机。**继续训练**几千到上万步之后，验证集会在很短的窗口内跳到接近 100%。这个现象叫 **grokking（延迟泛化）**。
>
> 原因不是「练久了自然会」，而是内部**两个解在竞争**：查表的记忆解先到、权重范数大；学算法的泛化解后到、权重范数小。weight decay 一直在压低范数，等到泛化解的总损失低于记忆解，优化器就切过去了。而「突然」有相当一部分是**准确率这个阈值指标**把平滑变化显示成了断崖。

## 0. 先纠正传闻里的两个偏差

流传的版本大概是：「Codex 最初训练时很容易过拟合，题库里的全会、测试集很低；正常训练到过拟合就该停了，但研究员有事没管，训练了一轮又一轮，突然测试集正确率就上来了。」

这句话拆开看，一半对一半不对：

| 传闻 | 实际 |
| --- | --- |
| 模型是 **Codex** | 不是。原始实验是 OpenAI 2022 年的**小 Transformer 做模运算**，与代码模型无关 |
| 「训练集全会、测试集很低，继续练之后突然变好」 | **准确**，这就是 grokking 的标准形态 |
| 「研究员忘了关，跑了一轮又一轮」 | 起源故事确实这么讲（跑了约一周），但论文正文只写了「观察到很晚才泛化」，细节属于二手叙述 |
| 「正常训练到过拟合就该停」 | 这是**早停**这个经验规则，不是定律；grokking 恰好是它的反例 |

> [!warning] 别把它当成「Codex 的训练秘籍」
> Codex 那类大模型预训练和这个实验差了好几个数量级：数据近乎无限、验证损失平滑下降，不存在「训练集 100%、验证集随机」的极端形态。把 grokking 套到 Codex 身上，属于转述时的张冠李戴。

## 1. 现象：曲线长什么样

![[grokking-curve.svg]]

三条特征，缺一不可：

- **记忆期很短**：训练准确率在几百步内冲到 100%，验证准确率还在随机水平（模 113 时约 1/113 ≈ 0.9%）。
- **平台期很长**：验证曲线像一条死掉的水平线，看起来就是「彻底过拟合、没救了」。
- **跃迁很陡**：在某个步数附近，验证准确率在几千步内从随机冲到 95% 以上，而训练损失几乎没有可见变化。

如果你按常规做法在平台期早停，拿到的就是「训练满分、测试随机」的模型——而且你会以为这个任务只能这样。

> [!note] 「突然」有多突然
> 论文里的跃迁通常跨越几百到几千步。放在 10⁴ 步的尺度上很陡，但不是一步到位：它对应的是内部一条通路的**接管过程**，只是准确率这个指标把它压缩成了一条近乎垂直的线。详见第 5 节。

## 2. 最小复现配方

想亲手看一遍，任务越小越好。经典设置是**模 p 加法**：

- 数据：所有 `(a, b)` 组合，标签 `(a + b) mod p`，共 p² 个样本；
- 划分：只取其中 **30%** 做训练集，剩下 70% 做测试集（这一步是关键，数据越少越容易 grokking）；
- 模型：1 层 Transformer 或 2 层 MLP，宽度 128 量级；
- 优化：AdamW，**weight decay ≈ 1.0**，全批量，学习率 1e-3；
- 训练：跑到 10⁴–10⁵ 步，每 100 步记录一次训练/测试准确率。

```python
import torch

p = 113
a = torch.arange(p)
A, B = torch.meshgrid(a, a, indexing="ij")
X = torch.stack([A.reshape(-1), B.reshape(-1)], dim=1)  # (p², 2)
Y = ((A + B) % p).reshape(-1)

g = torch.Generator().manual_seed(0)
perm = torch.randperm(p * p, generator=g)
n_train = int(0.3 * p * p)
tr, te = perm[:n_train], perm[n_train:]

# 训练循环里每个 step 都做全批量前向 + 反向
# 关键超参：AdamW(lr=1e-3, weight_decay=1.0, betas=(0.9, 0.98))
# 关键观察：train_acc 很早到 1.0，test_acc 长期 ≈ 1/p，然后在某一步起飞
```

> [!tip] 复现时最值得改的三个量
> 1. **weight decay**：改成 0 或 0.01，大概率看不到 grokking；
> 2. **训练数据比例**：从 30% 提到 80%，跃迁会明显提前甚至消失；
> 3. **模型宽度**：太窄学不动，太宽记忆更容易、平台期更长。
>
> 具体数值以论文附录和复现代码为准，这里给的是量级。

## 3. 为什么会发生：两个解在竞争

![[grokking-two-solutions.svg]]

同一张「(a, b) → 答案」的映射，网络至少有两种写法：

| | 记忆解（memorization） | 泛化解（generalization） |
| --- | --- | --- |
| 做法 | 给每个训练样本单独留一个方向，查表 | 学一组频率固定的正余弦特征，用恒等式算 |
| 到达速度 | 快，几百步 | 慢，几千到上万步 |
| 训练集 | 100% | 也是 100% |
| 测试集 | ≈ 随机 | 接近 100% |
| 权重范数 | 大 | 小 |
| 参数效率 | 低：每个样本都要占容量 | 高：一条规则覆盖所有组合 |

### 3.1 记忆解为什么先到

它的梯度方向更「直接」：把样本 a 在嵌入里推到一个专属位置、再把输出抬到对应答案，是一条几乎不需要协调的路径。用优化的话说，这条路径在参数空间里更短、更浅。

代价是它**必须**用大权重：不同样本要被推到足够分开，logit 才能拉开，否则查表也会互相干扰。

### 3.2 泛化解为什么后到

它要先把「数」变成结构化的表示——比如模 p 加法里的傅里叶基——再让两层网络学会用乘法把两个相位拼起来。这件事没法一步到位：

- 频率必须先对齐（有用的频率被放大，噪声频率被压掉）；
- 多个频率之间要形成一致的分工；
- 在这些完成之前，它在总损失里的贡献**完全被记忆解盖住**，梯度信号很弱。

换句话说：泛化解不是「没在学」，而是**学了但看不出效果**。

### 3.3 那最后为什么是它赢

因为 weight decay。它每一步都在把权重往 0 拉，而两个解要表达同一条规则时，需要的范数差很多：

- 记忆解：范数大 → 被惩罚得更狠，损失逐渐回升；
- 泛化解：范数小 → 几乎不受影响，反而随着结构成形持续下降。

两条损失曲线一定会交叉。**交叉点就是切换点**：优化器开始把容量从记忆解搬到泛化解，验证准确率随之起飞。Varma 等人把这个说法形式化成「电路效率」——用总参数范数归一化后的损失来比较两种解，效率高的那个最终胜出。

> [!important] 关键推论
> grokking 不是「时间久了自动变聪明」，而是**正则化在改变两种解相对成本**。所以正则越强（在合理范围内），跃迁越早；数据越多，记忆解越难建立，跃迁也越早。

## 4. 「突然」的三种解释层次

![[grokking-three-phase.svg]]

### 4.1 度量层：准确率是个阈值

模型输出的是 logit，正确类的 margin 从负数慢慢爬到正数，中间穿过 0。准确率只看符号，于是**平滑的 margin 变化被显示成断崖**。

这一层解释了「为什么看起来突然」，但解释不了「为什么之前一直不涨」——所以还需要下面两层。

### 4.2 机理层：记忆 → 回路形成 → 清理

Nanda 等人对模加法做了机制分析，把过程拆成三段，并造了两个可观测的量：

- **restricted loss**：只保留「泛化回路」那部分参数时的损失；
- **excluded loss**：把泛化回路去掉、只用其余参数时的损失。

三段的形态是：

1. **记忆**：总损失靠查表压下去，excluded loss 很低，restricted loss 还很高；
2. **回路形成**：restricted loss 独自下降，但总损失看不出变化，因为记忆解还压着；
3. **清理**：weight decay 把记忆解的权重压垮，excluded loss 崩塌，restricted loss 接管——这一步才对应验证准确率的跃升。

他们进一步证明，模型确实学出了**傅里叶乘法电路**：嵌入变成一组固定频率的正余弦，MLP 用三角恒等式算出 `cos(ω(x+y))`，输出层再对频率取最大。这是一条真正的算法，而不是查表。

### 4.3 优化层：弹射与双盆地

还有一类解释来自优化器本身：

- **Slingshot（弹射）**：Adam 这类自适应优化器会让权重范数出现周期性突跳，grokking 常常和其中一次弹射对齐；
- **Omnigrok**：把训练看成「权重范数要先长到某个临界值」的过程，landscape 上有两个盆地，模型要先爬出去才能掉进泛化盆地；初始范数越大，要爬的路越短，跃迁越早。他们还证明这个现象不只出现在算法任务上，MNIST、IMDb 上也能构造出来。

这三层不冲突：度量层解释「看起来多突然」，机理层解释「换了什么」，优化层解释「为什么在这个时刻换」。

## 5. 那条傅里叶回路到底在算什么

![[grokking-fourier-circuit.svg]]

模 p 加法的本质是**圆周上的旋转**：把数 x 对应到单位圆上角度 `2πx/p` 的点，`x + y` 就是把点再转 `2πy/p`。

于是有一条现成的恒等式可用：

```
cos(ω(x+y)) = cos(ωx)·cos(ωy) − sin(ωx)·sin(ωy),  ω = 2πk/p
```

模型要做的事就变成：

1. 嵌入层把 x 映射成 `cos(ωx), sin(ωx)`（对多个频率 k 同时做）；
2. 中间层做「两两相乘再相加」，得到每个频率上的 `cos(ω(x+y))`；
3. 输出层在这些频率的得分里挑出正确的那个余数。

> [!note] 为什么这算「学会了」而不是「背下来了」
> 这条通路对**任何** (x, y) 都成立，包括训练时没出现过的组合；它依赖的是任务本身的代数结构，而不是某个样本的编号。这也解释了泛化：参数只编码了「频率集合」，没编码「样本清单」。

代价对比也很直观：查表要 O(p²) 量级的容量，傅里叶写法只要 O(p·K)。

## 6. 哪些旋钮控制它

![[grokking-knobs.svg]]

按影响从大到小：

1. **weight decay**：最关键。调到 1.0 量级，跃迁能提前几个数量级；设成 0，很多设置下干脆不泛化。
2. **训练数据比例**：数据越少，记忆解越容易建立、平台期越长；接近全覆盖时，模型一开始就难以过拟合，grokking 退化成普通收敛。
3. **模型宽度 / 层数**：容量大 → 记忆更容易 → 平台期可能更长；容量太小 → 连记忆解都学不好。
4. **初始化尺度**：初始权重范数越大，离「临界范数」越近，跃迁越早（Omnigrok 的角度）。
5. **优化器与学习率**：Adam 的弹射是触发器之一；换 SGD、改 betas、改 schedule 都会改时间点。
6. **任务结构**：能被「算法化」的任务（模运算、群运算、排列复合）最容易出现；纯查表型任务没有可学的结构，就不会有跃迁。

> [!warning] 这些方向不是普适定律
> 换任务、换架构，「容量大更晚还是更早」可能反过来。可靠的只有一条：**所有旋钮都在改「记忆解与泛化解的相对效率」**。

## 7. 边界：什么时候不该指望它

> [!danger] 三个不要
> 1. **不要**因为 grokking 就取消早停。绝大多数真实训练里，平台期就是真的到顶了。
> 2. **不要**把「验证集卡住」直接归因于 grokking。先排除数据泄漏、标签错误、评测 bug、train/val 分布不一致。
> 3. **不要**用它解释大模型预训练里的「能力突现」。那是另一个维度（规模），机制也不同。

具体到场景：

- **大模型预训练**：数据近乎无限，训练/验证损失同步平滑下降，不会出现「训练 100%、验证随机」的极端过拟合形态。偶尔看到的「某个 benchmark 突然涨」更多和能力组合、评测指标有关。
- **小数据微调 / 合成任务**：有可能遇到延迟泛化。近年确实有工作在真实任务上报告了类似现象，但稳定性和幅度远不如小算法任务。
- **玩具任务复现**：这是它最可靠的主场，也是理解机制的最好入口。

## 8. 实践清单

如果你怀疑自己撞上了 grokking，按这个顺序查：

- [ ] 先确认 train/val 同分布、没有泄漏，评测脚本没写错；
- [ ] 同时画 **val loss** 和 **val 准确率**，别只看准确率；
- [ ] 保留多个 checkpoint（尤其是平台期中后段），不要只存最后一个；
- [ ] 扫一遍 weight decay（1e-2 / 1e-1 / 1.0）；
- [ ] 扫一遍数据比例，确认不是「数据太少导致的假过拟合」；
- [ ] 记录「泛化发生步数」，和 weight decay、数据比例画成二维关系；
- [ ] 预算有限时先用 p=97/113 的小任务确认现象，再迁移判断。

## 9. 和相邻概念的区别

| 现象 | 变化的是 | 曲线形态 | 典型场景 |
| --- | --- | --- | --- |
| Double descent | 模型容量 / 参数量 | 测试误差随容量先降后升再降 | 小数据、过参数化网络 |
| Grokking | 训练时间 | 测试准确率长时间平台后跃升 | 小算法任务、强正则 |
| Emergence | 模型规模 / 数据量 | 能力随规模「突然出现」 | 大模型 benchmark |

三者有一个共同的方法论警告：**曲线的「突然」很可能是指标造成的**。Schaeffer 等人就论证过，很多「涌现能力」换一个连续指标就变成平滑上升；grokking 的陡峭程度同样受指标影响。但 grokking 有额外的机制证据（回路替换是可观测的），所以它比「纯指标幻觉」更实在。
