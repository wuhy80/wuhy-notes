### [Claude Code 新增 claude plugin eval，评估插件或skill](https://x.com/ClaudeDevs/status/2098500999656923145) `#5`
> **Claude Code** 新增 `claude plugin eval`命令，可创建测试用例并对比带插件与不带插件的得分，用于评估插件或 `skill` 的实际价值。

**Claude Code** 新增 `claude plugin eval` 命令，用于评估插件或 skill 的实际价值。

用户运行 `claude update` 即可试用。

开发者可在插件目录运行 **`claude plugin eval init`**，向 **Claude** 描述好坏输出的标准并提供若干真实提示词，由 **Claude** 起草测试用例和检查项、试点运行并预估完整运行成本。

随后运行 **`claude plugin eval`**，终端会显示每个用例带与不带插件的得分，并生成包含完整细节的 **HTML** 报告。若账户支持，报告还会发布为私有 **artifact**。

**官方** 提醒，评估会调用模型、消耗 **token** 且结果存在波动，建议先用 `--runs 1` 试点。评估时插件的 `hooks` 和 `MCP` 服务器会以用户本人身份运行，只应评估可信的插件。

### [OpenAI 发布 GPT-6 Astra 提示词与 skills 重构指南](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) `#9`
> **OpenAI** 开发者账号发文，建议针对 `GPT-6 Astra` 重新梳理 `skills`、`AGENTS.md` 和任务提示词，明确触发与完成标准。

**OpenAI** 开发者官方发布指南，建议开发者在使用 `GPT-6 Astra` 时重新审视项目中的 `skills`、`AGENTS.md` 和任务提示词。

官方称，模型能力增强后，过去需要大量引导和脚手架的做法已不再必要，过长或过多的 `skill` 描述会占用上下文、触发 `Codex` 截短描述，导致模型难以选对工具。

指南建议把 `skill` 触发条件写得更具体、让根文档充当指向子文档和脚本的最小路由，并按任务上下文指向文档，而非要求每次编辑前通读。

针对 `GPT-6 Astra` 在停止时机上更谨慎的倾向，官方建议事先定义完成标准，把实现、检查和修复明确写入任务范围。

### [Devin Desktop 和 CLI 推出 Fusion 双模型模式](https://cognition.com/blog/local-fusion) `#11`
> **Cognition** 在 `Devin Desktop` 和 `CLI` 推出 **Fusion 双模型模式**，前沿模型负责规划审查，低成本模型负责执行。官方称 `Fusion` 在主要编码基准上最高比其他模型 `harness` 便宜 **39%**。

**Cognition** 正式在 `Devin Desktop` 和 `Devin CLI` 中推出 `Fusion`，目前即可使用。

`Fusion` 采用两个并行 **Agent** 的架构：`lead` 由前沿模型担任，负责规划、歧义解读和审查；`sidekick` 由高性价比模型担任，负责探索代码、实现修改和运行测试。

两者只交换任务简报、结果和反馈，各自维护独立上下文以利用 `prompt` 缓存，`lead` 始终掌管会话并可在 `sidekick` 力不从心时收回控制。

官方称 **Fusion** 是 `Fable` 和 `Astra` 最高效的前沿 `harness`，在主要编码基准上最高比其他模型 `harness` 便宜 **39%**，推荐组合为 `Fable 5.1` 搭配 `SWE-2`。
