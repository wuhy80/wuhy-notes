### [Sakana AI推出多Agent编排系统Fugu](https://sakana.ai/fugu/) `#4`
> **Sakana AI**推出多Agent编排系统 `Fugu`，分为标准版和 `Ultra` 版，通过单一 `OpenAI` 兼容API动态协调多个闭源模型。官方称其在编程、推理等基准中与 `Fable 5` 齐肩，但遭到大量的质疑。

近日，**Sakana AI** 推出了多 Agent 编排系统 `Fugu`。

该系统包含 `Fugu` 和 `Fugu Ultra` 两个版本。

两个版本均可通过单一的 `OpenAI` 兼容 `API` 访问，无需 `SDK` 迁移。

官方称，`Fugu` 本身是经过训练的，能够动态调用 `Agent` 池中多种闭源模型的 `LLM`（包括递归调用自身）。

在编程、推理等基准测试中，它超越了部分公开前沿模型，与 `Fable 5` 和 `Mythos Preview` 处于同一梯队，且无出口管制风险。

其中，`Fugu Ultra` 通过更深层次的 `Agent` 协作，优先优化复杂任务的质量，但其 `Agent` 池固定，用户不可调整。

`Fugu` 标准版则允许用户排除特定模型，以满足合规需求。

但社区成员质疑，该系统是在闭源模型之上叠加了闭源编排器。

用户无法控制使用哪些模型及具体用量，因此并非真正的 **“AI 主权”**。

此外，官方未公布任何基准测试的 **token 消耗** 和 **成本**。

其匿名化对比模型的做法，也缺乏透明度。

**Nous Research** 官方宣布，`Hermes Agent` 的 `Computer Use`（电脑控制）功能已正式从原有的 `macOS` 扩展至 **Windows** 和 **Linux** 平台。

该功能通过开源的 `cua-driver` 在后台运行，允许 `AI` 读取无障碍树并执行点击、输入等操作，同时不移动真实的系统光标。

### [Google 正式发布 Interactions API 成为 Gemini 默认接口](https://blog.google/innovation-and-ai/technology/developers-tools/interactions-api-general-availability/) `#8`
> **Google** 宣布 **Interactions API** 正式发布，并成为 `Gemini` 模型与 `Agent` 的默认接口。该 API 支持在同一界面编排模型与 `Agent`，新增 `Managed Agents` 和后台执行等功能，现已开放使用。

**Google** 宣布 `Interactions API` 正式发布（GA），该 API 专为在单一端点中编排 `Gemini` 模型与自主 Agent 而设计，现已取代旧版成为默认的交互接口。

此次 **GA** 版本引入了稳定的 `schema` 及多项新能力。包括通过单次调用配置远程 `Linux` 沙盒的 `Managed Agents`、异步处理长耗时任务的 `后台执行功能`，以及结构化为独立步骤的简化数据模式。

同时，该 API 扩展了工具生态，原生支持 **Google Maps** 等工具组合，并集成了图像、音乐及多发音人语音生成等多模态能力。

目前开发者可通过 `Python` 和 `JavaScript SDK` 使用该 API。旧的 `generateContent API` 仍受支持，但前沿的长时间运行和 `Agent` 能力将逐步专供新接口。

### [京东开源实时视觉交互模型JoyAI-VL-Interaction](https://github.com/jd-opensource/JoyAI-VL-Interaction) `#10`
> **京东**团队开源了8B视觉语言交互模型`JoyAI-VL-Interaction`及可部署系统。官方称该模型能持续观察视频流并在一秒内主动响应，在实时交互场景的人工评测中优于**豆包**和`Gemini`。

**京东**团队正式开源了 **8B** 规模的视觉语言交互模型 `JoyAI-VL-Interaction` 及其完整技术栈。
