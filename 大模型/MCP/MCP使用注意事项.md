MCP 内部不适合再次封装 Agent，因为本身 Agent 的调用有超时的限制，如果再叠加一个内部去调用大模型的操作，会导致超时严重。
在 MCP Server 里面应该只处理查询数据库，查询本地文件等相对比较直接的操作，可以通过 `ctx.report_progress(i, len(files))` 的方式上报一些处理过程中的状态信息
当前的 FastMCP 不支持 steam 的方式返回

| 原语             | 控制   | 示例               |
| -------------- | ---- | ---------------- |
| 提示 (Prompts)   | 用户控制 | 代码审查提示、调试错误提示    |
| 资源 (Resources) | 应用控制 | 用户配置文件、静态数据      |
| 工具 (Tools)     | 模型控制 | 计算 BMI、获取天气、文件操作 |
