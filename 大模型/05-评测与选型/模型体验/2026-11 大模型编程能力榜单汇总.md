# 2026-11 大模型编程能力榜单汇总

> [!summary] 一句话结论
> 编码能力目前是 **Anthropic 领跑**（Claude Opus 5.5 / Fable 5.1 几乎霸榜前三），**OpenAI GPT-6.1 Sol** 在「网页生成 + 人类盲投」类榜单上反超且性价比最高，**Google Gemini 4（Carbon / Argon）** 稳居前三；国产阵营强在**开源权重、上下文长度和价格/性能比**——DeepSeek V4 Pro、Qwen3.7 Max、GLM-5.2、Kimi K3/K3.1 各自占位。

> [!warning] 别跨表比数字
> 同一个 SWE-bench Verified，不同站点从 80% 到 95% 都有；差异来自**是否带工具、harness 实现、重试次数、评测集版本**。下表每条都标了快照日期与来源，「谁在上升」比具体小数更可信。

## 六、评测协议差异（读榜前必看）

同样的模型名，换一套评测协议就能差出一个量级。下面按「变量 → 影响幅度 → 哪些榜受影响」拆开。

### 6.1 六个决定性变量

| 变量 | 常见取值 | 影响幅度 | 典型受影响榜 |
|---|---|---|---|
| **子集** | Verified 500 / Lite 300 / Full 2294 | 3–8 个点（子集难度不同） | SWE-bench 系、BigCodeBench（Complete/Hard） |
| **harness / Agent** | SWE-agent、mini-swe-agent、Claude Code、Codex、OpenHands、自研 | **5–15 个点**，最大变量 | SWE-bench 系、Terminal-Bench、SWE-Pro |
| **是否带工具** | 纯生成 vs 可执行 bash/编辑/搜索 | 5–12 个点 | SWE-bench、Terminal-Bench |
| **重试与采样** | pass@1 vs best-of-5/N | best-of-N 虚高 3–10 点 | Codeforces、SWE-bench 自报成绩 |
| **推理档位** | thinking off / low / high / max | 3–8 个点 | LMArena（Max/xHigh 等设置）、AA 系列 |
| **版本切片** | 时间窗口（防污染）、榜单版本 | **跨版本不可比** | LiveCodeBench v5、Terminal-Bench 2.x→4.x、SWE-Pro→Pro V2 |

### 6.2 各榜的协议细节

| 榜单 | 跑法 | 是否带工具 | 判定方式 | 特别之处 |
|---|---|---|---|---|
| **SWE-bench Verified** | 模型 + scaffold 一起提交；官方榜（swebench.com）只收 leaderboard 提交 | 多数带（bash + 编辑） | 仓库自测通过 | 500 条人类筛选 issue；同一模型换 harness 名次会变 |
| **SWE-bench Pro / Pro V2** | 固定三种 harness（Claude Code / Codex / mini-swe-agent），无联网，≤250 轮 | 带（受控） | 新测试过 + 既有测试不回归 | 含私有商用集，公开集只有一部分；污染控制更严 |
| **Terminal-Bench 4.1** | 容器内真实执行终端任务，模型 + agent 成对上报 | 带 | 任务检查器 | 4.1 专门强化 verifier 防作弊；同时报 token 与美元成本 |
| **LMArena WebDev** | 匿名两两对比，人类盲投 | 不带（只生成前端产物） | 投票（Elo 类） | **不是自动评测**；日更、波动大；镜像站抓取时点不同则名次不同 |
| **AA Coding Index** | 复合指数，聚合多个子项 | 混合 | 归一化加权 | 数据来自独立跑分 + 厂商自报，页面会标 provider-reported |
| **AA LiveCodeBench** | 二次汇总的 LiveCodeBench 结果 | 通常不带 | 测试通过率 | 官方声明「仅供参考、不用于排名」 |
| **LiveCodeBench / v5** | 只取模型训练截止后的新题 | 不带 | pass@1 | 时间窗口切片；v5 是命名切片，**不能与 rolling 榜混用** |
| **LiveBench 2.0** | 每月换题、客观判分 | 部分 suite 带 | 自动判分（无人类/无 LLM 裁判） | 污染控制设计；分 Coding/Agentic/Design/Reasoning 等 suite |
| **BigCodeBench** | 函数级补全，沙箱执行 | 不带 | pass@1 | Hard 子集需要多库组合调用；**依赖库版本会影响结果** |
| **Aider polyglot** | 225 道 Exercism、6 语言 | 带（编辑文件） | 单测通过 | 关键变量是 **edit format**（diff/diff-fenced/whole/architect）与 thinking tokens；最多重试 3 次 |
| **Codeforces Elo** | 竞赛题实时评分，映射人类 Elo | 一般不带 | 通过与否 + 罚时 | best-of-N 会明显虚高；难度分布不同则分数漂移 |
| **Bug Bench** | 真实代码修改的缺陷统计 | — | 相对 bug 率（1.0=平均） | 与能力榜不同维度，不能换算成分数 |

### 6.3 读榜四问（拿到任何数字先问这四句）

> [!important] 四问清单
> 1. **哪个子集？** Verified(500) 还是 Lite(300)/Full(2294)；BigCodeBench 是 Complete 还是 Hard。
> 2. **什么 harness？** 模型单跑，还是套了 Claude Code / Codex / SWE-agent；有没有联网、轮数上限多少。
> 3. **pass@1 还是 best-of-N？** 自报成绩里 best-of-N 很常见，对外比要统一到 pass@1。
> 4. **哪个版本切片？** Terminal-Bench 4.1 的 65.8% 不能和 2.0 的数字比；LiveCodeBench v5 也不能和 rolling 榜混。

### 6.4 经验折扣表（用于快速对齐不同来源）

| 情况 | 建议折扣 | 说明 |
|---|---|---|
| 带工具 + 最优 harness（如 Claude Code） | 数字可信，但要问清 harness | 直接对比须同 harness |
| best-of-N（N≥5） | 打 5–8 折视 pass@1 | 竞赛类尤其明显 |
| 厂商自报、无第三方复测 | 打 8 折 | 常见于 90%+ 的 SWE 数字 |
| 只给单点、无样本量/方差 | 只作参考 | Terminal-Bench 会给 ±3.1% 这种区间，可优先采信 |
| 跨版本（2.x vs 4.x） | **不可比** | 题目与 verifier 都变了 |
| 跨子集（Verified vs Lite） | **不可比** | 难度分布不同 |

### 6.5 顺带一句：榜单之间的"排名"也常冲突

- **能力 vs 成本**：Terminal-Bench 上 Opus 5.5 解决率最高，但 GPT-6.1 Sol 用 1/8 成本达到九成；
- **能力 vs 稳定**：Bug Bench 上 Opus 5.5 的 bug 率在头部里最高（1.25）；
- **人类偏好 vs 自动评测**：LMArena 上 GPT-6.1 Sol 领先，但 SWE 系里 Anthropic 更稳——它们衡量的根本不是同一件事（前者是"看起来像不像好网页"，后者是"改完测试过不过"）。

> [!tip] 实用做法
> 先按**你的 harness 和子集**选 2–3 个候选，再用自己仓库的 20–30 个真实任务做 A/B；公开榜单只用来决定"要不要试这个模型"，不用来定"选哪个"。

## 七、数据可信度与更新节奏

> [!warning] 四条注意事项
> 1. **同模型跨站可差 10–15 个点**：工具、harness、重试次数、子集划分都不同；
> 2. **竞技场类是人主观投票**，日更且波动大，适合看趋势不适合抠排名；
> 3. **厂商自报的 90%+ 要打折看**，优先找第三方复测（Epoch AI、Artificial Analysis、Scale 等）；
> 4. 上面每张表都标了快照日期，做决策前请回到最新快照复核。

- 汇总站：BenchLM、LMMarketCap、Airating、llmbenchmark、ULTRABENCH（取数口径各异，务必看「source / 更新日期」字段）。
- 官方/准官方：LMArena（webdev-arena）、Scale AI SWE-bench Pro、Snorkel Terminal-Bench、Artificial Analysis、LiveBench、Epoch AI。
- 更新节奏：LMArena 每日、AA 每 1–2 周、SWE-bench 系随新模型发布、Terminal-Bench 按版本迭代。
