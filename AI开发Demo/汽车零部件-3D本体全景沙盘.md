# 汽车零部件 · 3D 本体全景沙盘

> [!summary] 一句话
> 75 个本体节点、5 大分区、6 类接口契约，外加 731 张历史源表的 SQL 映射。**刀装工具沙盘就是照着它的视觉与交互语言做的**，所以放在本专题里当参考基线。

## 一、它的结构

| 视图 | 内容 |
| --- | --- |
| 3D 本体全景沙盘 | 五层平板（M2 / L1 / L2 / L3 / L4）× 五个 Scope 分区，节点按原型画形状，连边带动词 |
| 标准对照 | 分层语义（Palantir / BFO / ISA95 对照），回答「这一层到底是什么」 |
| 角色泳道 | 五个角色（物联主数据 / 业务域 / 系统集成 / AI 算法 / 平台内核）各自的职责与红线 |
| SQL 映射 | 731 张源表的五级漏斗：入图 / 下沉时序 / 折叠 / 划归数仓 / 剔除 |

## 二、值得抄的五点

1. **分层平板当抽象层级**：比单纯的 3D 力导向图更容易讲清「L1 实物 → L2 规则 → L3 单据 → L4 算子」。
2. **分区底板**：同层内用色块圈出业务域，观众不需要读图例就知道这块归谁。
3. **接口契约环**：节点外面的同心椭圆环表示它实现了哪些 Interface，一眼看出「谁挂了契约」。
4. **动词连边**：边上写 `inherits_abstract / 继承空间基类` 这类动词，关系读得出来。
5. **视检抽屉**：点节点出详情 + 上下游关系 + 可跳转，比弹窗不打断空间感。

## 三、和刀装工具沙盘的差异

| | 汽车零部件（参考基线） | 刀装工具（本次实现） |
| --- | --- | --- |
| 体量 | 75 节点 / 5 Scope / 6 视图 | 34 节点 / 5 分区 / 4 视图 |
| 高亮方式 | 点击选中后高亮邻域 | **悬浮即高亮**，并按上游/下游分色 |
| 流程演示 | 8 个场景一次性点亮 | **逐步播放**，当前步/已完成/未到三态 |
| 标签 | 选中态优先 | 统一落位队列 + 碰撞仲裁 |
| 主题 | 深/浅双色 | 同，且修正了浅色下阴影发灰的问题 |

## 四、什么时候还该看它

- 要做**本体/知识图谱类**沙盘，而不是「零件装配」类沙盘时；
- 需要论证「分层 + 分区」这种结构为什么成立时；
- 需要给业务方解释「为什么 731 张表最后只剩这么几个对象」时（SQL 映射视图的漏斗图）。
