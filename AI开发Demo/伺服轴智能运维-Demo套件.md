# 伺服轴智能运维 · Demo 套件

> [!summary] 一句话
> 同一家工厂、同一条伺服轴产线的三份演示材料：**一页叙事**（demo-3d）、**一台机床的实时镜像**（demo-twin）、**一份七幕串场稿**（演示脚本）。讲的时候按「叙事 → 镜像 → 脚本」的顺序走。

| 文件 | 作用 | 体积 |
| --- | --- | --- |
| `assets/demo-3d.html` | 产线 3D 全闭环叙事页，六段式滚动推进：订单 → 排程 → 加工 → 质量 → 能耗 → 复盘 | 132 KB |
| `assets/demo-twin.html` | 单机数字孪生镜像（CNC-012），六个环节的实时看板 | 758 KB |
| `assets/伺服轴智能运维Demo演示脚本.html` | 七幕场景说明，讲清每屏在说什么、谁来讲 | 71 KB |

三个页面都是自包含 HTML，双击即开。

## 一、demo-twin.html：一台机床怎么被映射成数据

这是三份里信息密度最高的一份，演示的是「设备孪生体」：

- **左上 HUD**：健康度弧形仪表（HEALTH 86 · 良好 · 平稳）、主轴 X / Y / Z 三轴负载、刀具寿命与 VB 磨损值
- **右上 HUD**：随环节切换的解说面板（`环节 01 · 全域感知` → `环节 06 · 审核下发`）
- **底部状态条**：主轴 / 冷却 / 门联锁 / 润滑 四个运行状态，异常的会标黄
- **24h 趋势条**：可视化的历史负载，用来支撑「为什么现在报警」
- **报警层**：出现异常时整屏边缘泛红 + 顶部 toast，不用观众去找哪里变了
- **交互**：`外罩：开/关` 切换能看见内部结构；`▶ 自动演示` 按六环节自动走完一轮

**六个环节的闭环**（这是它真正想讲的）：

| # | 环节 | 在演什么 |
| --- | --- | --- |
| 01 | 监控大屏 | 全域感知：设备在干什么 |
| 02 | 异常报警 | 参数超标：哪一项越界了 |
| 03 | 数字人分析 | AI 解析：可能是什么原因 |
| 04 | 人工研判 | 人机协同：人确认/否决 |
| 05 | 工单方案 | 智能处置：建议怎么修 |
| 06 | 审核下发 | 派工：谁在什么时候去修 |

> [!tip] 演示时的讲法
> 不要一上来讲技术架构。先用「这台机床现在健康度 86」把人带进来，再让报警触发，最后讲「从报警到派工单，中间没有一次手工抄表」——闭环是靠这条链路立住的。

## 二、demo-3d.html：产线级的叙事页

如果 demo-twin 是「显微镜」，这份就是「全景图」：六段式滚动叙事，把订单接入、APS 排程、加工执行、质量追溯、能耗与碳、复盘改善串成一条线。适合开场 3 分钟建立全局印象。

## 三、演示脚本：讲的人手里的那张纸

七幕场景说明，每一幕给出画面要点、讲解口径和串场句。它本身不是给观众看的，是给讲的人看的——**建议最后才打开**，否则会把注意力从画面上带走。

## 四、三份材料的关系

```text
叙事（demo-3d）       ：为什么要做这件事
镜像（demo-twin）     ：这件事在设备上长什么样
脚本（演示脚本）      ：讲的时候怎么串
```

## 五、可复用的做法

1. **环节式推进**：把「智能运维」拆成 6 个可点击的环节，比一张大屏更能讲清闭环。
2. **报警要有物理位置**：整屏边缘泛红 + toast + 对应面板高亮，三处同时变，观众才看得见。
3. **状态条固定四项**：主轴 / 冷却 / 门联锁 / 润滑——不多不少，正好覆盖「能不能继续干」。
4. **数字孪生不等于 3D 模型**：真正起作用的是参数、状态、趋势和报警之间的对应关系。
